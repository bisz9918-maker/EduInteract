[图示主题与整合说明]
- 本图示主题：旋转全等三角形中的角度推导
- 整合的步骤/概念：
  1. 原始图形与旋转后图形的整体呈现（△OAB 与 △OCD）
  2. 已知条件标注（旋转角 70°、∠A=100°、∠D=50°）
  3. 全等关系与对应角相等的可视化（△OAB≌△OCD）
  4. 利用三角形内角和求 ∠AOB（或 ∠COD）= 30°
  5. 通过旋转角与 ∠AOB 的差计算 ∠AOD = 40° 并给出选项结论
- 教学价值：教师通过分步导航控制课堂节奏，从识图→标条件→用性质→计算→得结论，每一步可回退复习，适合引导学生逐步建立几何推理链。

[分步序列]
- 步骤0（识图·初始状态）：
  显示 △OAB（蓝边）、△OCD（红边）及五个顶点标签 O、A、B、C、D。无任何角度弧线、填充或说明文本。引导学生观察两三角形的旋转位置关系。

- 步骤1（标已知）：
  点击「下一步」后新增：
  · ∠AOC 红色弧线（r=50）及标注 "70°"（O 上方偏左）
  · ∠A 蓝色弧线（r=25）及标注 "100°"（A 下方偏左）
  · ∠D 红色弧线（r=25）及标注 "50°"（D 左下方）
  · 右侧文本 "已知：旋转角 ∠AOC = 70°，∠A = 100°，∠D = 50°"
  保留步骤0 的所有元素。

- 步骤2（显全等）：
  点击「下一步」后新增：
  · △OAB 蓝色填充（opacity 0.20）、△OCD 红色填充（opacity 0.20）
  · 右侧文本 "△OAB ≌ △OCD"（△OAB 蓝字，△OCD 红字，≌ 黑字）
  · 右侧文本 "∴ ∠B = ∠D = 50°"
  · 右侧文本 "∠C = ∠A = 100°"
  保留步骤0~1 的所有元素。

- 步骤3（求第三角）：
  点击「下一步」后新增：
  · ∠AOB 绿色弧线（r=35，OB 与 OA 之间）及标注 "30°"（O 右下方）
  · ∠COD 绿色弧线（r=35，OD 与 OC 之间）及标注 "30°"（O 左上方）
  · 右侧绿色文本 "∠AOB = 180° − 100° − 50° = 30°"
  保留步骤0~2 的所有元素。

- 步骤4（得结论）：
  点击「下一步」后新增：
  · ∠BOD 红色弧线（r=45，OB 与 OD 之间）及标注 "70°"（O 右上方）
  · ∠AOD 绿色弧线（r=55，OA 与 OD 之间，外扩）及标注 "40°"（O 上方偏右，加粗）
  · 右侧绿色文本 "∠AOD = ∠BOD − ∠AOB = 70° − 30° = 40°"
  · 右侧绿色加粗文本 "答案：C. 40°"（字号 18px）
  保留步骤0~3 的所有元素，形成完整推导图。

[交互方案]
- 交互类型：分步按钮导航（◀ 上一步 / 下一步 ▶）
- 控件说明：
  · 「上一步」按钮：位于 (300, 455)，宽 80×高 30，点击回退到上一状态。
  · 「下一步」按钮：位于 (420, 455)，宽 80×高 30，点击推进到下一状态。
  · 步骤指示器：位于 (200, 470)，显示 "步骤 X/4"，提示当前进度。
- 教师操作流程：
  1. 教师展示步骤0，让学生观察两个三角形的旋转关系；
  2. 点击「下一步」进入步骤1，引导学生读取已知角度；
  3. 点击「下一步」进入步骤2，强调全等与对应角；
  4. 点击「下一步」进入步骤3，利用内角和求出 30°；
  5. 点击「下一步」进入步骤4，通过旋转角差求出 40° 并锁定选项 C；
  6. 可随时点击「上一步」回退，强化关键步骤。

[技术实现]
- JS 库选择：原生 SVG（使用 <svg>、<path>、<line>、<text> 等基础元素）。理由：本场景为静态几何图形与简单显隐切换，无需复杂绘图库，原生 SVG 即可精确控制每个元素的坐标与样式，且性能最优。
- 画布尺寸：800 × 500 px（固定）。
- 布局草图（ASCII）：
  ```
  +----------------------------------------------------------+
  |                                                          |
  |   C ●              D ●                                   |
  |      \            /                                      |
  |       \   △OCD   /                                       |
  |        \   红    /                                        |
  |         \       /                                         |
  |          \     /                                          |
  |           \   /                                           |
  |            ● O                                            |
  |           / \                                             |
  |          /   \                                            |
  |         /     \                                           |
  |        /  △OAB \                                          |
  |       /   蓝    \                                         |
  |      /           \                                        |
  |   A ●             ● B                                     |
  |                                                          |
  |    [右侧文本区：全等式、计算式、答案]                      |
  |                                                          |
  |  步骤 X/4    [上一步]  [下一步]                           |
  +----------------------------------------------------------+
  ```
- 关键实现要点：
  1. 状态机设计：使用变量 `let currentStep = 0;`（范围 0~4）。每一步对应一组元素的 `display` 属性切换（`block`/`none` 或 SVG 的 `visibility`）。
  2. 坐标计算：O 点定位 (280,380)。OA=140px（方向屏幕角 −50°），OB=180px（方向屏幕角 −20°），OC=140px（方向屏幕角 −120°），OD=180px（方向屏幕角 −90°）。角度弧线使用 SVG `<path>` 的 `A` 命令，通过三角函数计算起点/终点坐标，sweep-flag 统一为 0（数学逆时针）。
  3. 动画曲线：本场景无需复杂动画，元素直接显隐即可；如需柔和过渡，可对 `opacity` 施加 200ms CSS transition。
  4. 事件绑定：为「上一步」「下一步」按钮绑定 `click` 事件，更新 `currentStep` 后调用 `renderStep()` 统一刷新视图。
  5. 文本颜色混合：全等式 "△OAB ≌ △OCD" 使用三个 `<tspan>` 分别着色（△OAB 蓝、≌ 黑、△OCD 红）。
  6. 防重叠：∠AOD 弧线使用 r=55（大于 ∠AOC 的 r=50），确保两弧线在 O 点上方不重叠；所有文本标签严格按坐标表定位。
- ID 命名规范：所有交互元素 ID 必须以 `scene1-` 为前缀。例如：
  · `scene1-vertex-o`、`scene1-vertex-a`、...
  · `scene1-side-oa`、`scene1-side-ab`、...
  · `scene1-angle-aoc`、`scene1-angle-a`、...
  · `scene1-fill-oab`、`scene1-fill-ocd`
  · `scene1-text-known`、`scene1-text-cong`、`scene1-text-calc-aob`、...
  · `scene1-btn-prev`、`scene1-btn-next`、`scene1-step-indicator`
  JS 中严格使用 `document.getElementById` 获取元素，禁止跨场景选择器。
- IIFE 隔离：所有 JavaScript 代码包裹在 `(function() { ... })();` 中，避免全局变量污染，确保多场景合并时互不干扰。
