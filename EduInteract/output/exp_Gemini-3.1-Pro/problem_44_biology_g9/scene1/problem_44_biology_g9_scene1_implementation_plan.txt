[图示主题与整合说明]
- 本图示主题：血液流经不同器官/结构时的血管类型及成分变化
- 整合的步骤/概念：将原图的抽象模型（甲→乙→丙）与四个具体选项（毛细血管网、小肠、肾小球、胰岛）结合，通过动态改变血管颜色、添加成分图标和文字标注，直观展示血液成分和血管类型的变化。
- 教学价值：教师可通过分步导航，逐一剖析四个选项的正误。动态的颜色变化和图标能有效打破学生的思维定势（如“流出器官的血管一定是静脉”），并清晰展示物质交换过程。

[视觉元素清单]
- 基础框架：
  - 矩形框（乙）：黑色边框 #000000，透明填充。
  - 箭头（甲、丙）：初始黑色 #000000，随状态变为红色 #c62828 或蓝色 #1565c0。
  - 固定标签：“甲”、“乙”、“丙”文本，黑色 #000000。
- 动态标签/图标：
  - 氧气（O₂）：红色 #c62828 文本。
  - 营养物质：绿色 #2e7d32 文本。
  - 葡萄糖：红色 #c62828 文本。
  - 胰岛素：绿色 #2e7d32 文本。
- 辅助说明：
  - 标题和结论文本：黑色 #000000，结论中强调部分可使用对应颜色。
  - 副标签：颜色与对应箭头一致。

[分步序列]
- 初始状态（步骤0）：
  - 标题：“血液流经不同器官的成分变化”
  - 乙标签：“乙”
  - 甲、丙箭头：黑色
  - 甲、丙副标签及图标：隐藏
  - 结论：“点击「下一步」分析各个选项”
- 步骤1（分析A）：
  - 标题：“选项A：若乙表示毛细血管网”
  - 乙标签：“毛细血管网
(特例:肾小球)”
  - 甲、丙箭头：红色（表示动脉血）
  - 甲副标签：“入球小动脉”；丙副标签：“出球小动脉”
  - 结论：“A错误：若为肾小球，则丙内流的是动脉血。”
- 步骤2（分析B）：
  - 标题：“选项B：若乙表示小肠”
  - 乙标签：“小肠”
  - 甲箭头：红色；丙箭头：蓝色（表示静脉血）
  - 甲副标签：“含氧丰富”；丙副标签：“含氧减少，营养增多”
  - 甲侧图标：“O₂ O₂ O₂”；丙侧图标：“O₂ 营养 营养”
  - 结论：“B错误：小肠消耗氧气，丙内含氧量应减少。”
- 步骤3（分析C）：
  - 标题：“选项C：若乙表示肾小球”
  - 乙标签：“肾小球”
  - 甲、丙箭头：红色
  - 甲副标签：“入球小动脉”；丙副标签：“出球小动脉”
  - 结论：“C错误：肾小球连的出球小动脉，是动脉血管。”
- 步骤4（分析D）：
  - 标题：“选项D：若乙是胰岛”
  - 乙标签：“胰岛”
  - 甲箭头：红色；丙箭头：蓝色
  - 甲副标签：“高血糖血液”；丙副标签：“胰岛素增多”
  - 甲侧图标：“葡萄糖 葡萄糖”；丙侧图标：“胰岛素 胰岛素”
  - 结论：“D正确：血糖升高刺激胰岛分泌胰岛素，随血液从丙流出。”

[标签冲突检查]
- 甲标签 (200, 220) vs 甲侧图标 (200, 170)：间距 50px。甲标签字高约 24px，顶部在 196px，图标底部在 170px，无冲突。
- 甲标签 (200, 220) vs 甲箭头 (100-300, 250)：间距 30px。标签底部在 225px，箭头在 250px，无冲突。
- 甲副标签 (200, 280) vs 甲箭头 (100-300, 250)：间距 30px。副标签顶部在 262px，箭头在 250px，无冲突。
- 丙侧同理，无冲突。
- 乙标签 (400, 250) vs 乙框 (300-500, 200-300)：标签居中于框内，框高 100px，标签最多两行（约 60px），无冲突。
- 结论文本 (400, 400) vs 乙框 (300-500, 200-300)：间距 100px，无冲突。

[交互方案]
- 交互类型：分步按钮导航（◀上一步 / 下一步▶）
- 控件说明：底部居中放置两个按钮，用于在 0-4 步之间切换。
- 教师操作流程：教师首先展示初始模型，然后点击“下一步”逐个分析 A、B、C、D 选项。每一步配合动态变化的颜色和图标，向学生解释为什么该选项正确或错误。可随时点击“上一步”回顾。

[技术实现]
- JS 库选择及原因：原生 SVG。本场景主要由简单的几何图形（矩形、线段、箭头）和文本组成，原生 SVG 易于实现精确布局和颜色/文本的动态更新，无需引入庞大的外部库。
- 画布尺寸：800 × 500 px
- 布局草图：
  ```
  [图示区 800×500]
    (标题区)
       甲侧图标          丙侧图标
         甲标签            丙标签
  -----> [      乙      ] ----->
       甲副标签          丙副标签
    (结论区)
  [控件栏：◀上一步  下一步▶]
  ```
- 关键实现要点：
  - 状态机设计：定义一个包含 5 个状态（0-4）的数组，每个状态对象包含所有需要更新的文本、颜色和可见性信息。
  - DOM 操作：通过 `getElementById` 获取 SVG 元素，在状态切换时更新其 `textContent`、`stroke`、`fill` 和 `opacity` 属性。
  - 箭头绘制：使用 `<marker>` 定义箭头，方便复用于甲、丙线段。
  - 多行文本：乙标签在步骤 1 中需要换行，使用 `<tspan>` 实现。
  - ID 命名规范：所有交互元素 ID 必须以 `scene1-` 为前缀（如 `scene1-title`, `scene1-arrow-jia`）。
  - IIFE 隔离：所有 JS 代码封装在 `(function() { ... })()` 中。
