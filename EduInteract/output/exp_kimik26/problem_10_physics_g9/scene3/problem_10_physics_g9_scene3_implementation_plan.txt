[图示主题与整合说明]
- 本图示主题：液体压强比较与底部压力和液体重力的关系
- 整合的步骤/概念：
  1) 由液面深度相同、液体质量相同但容器形状不同，推导出密度关系 ρ₁>ρ₂；
  2) 利用液体压强公式 P=ρgh 比较底部压强 P₁>P₂（结论③）；
  3) 通过侧壁对液体的压力分解，揭示上宽下窄容器侧壁对液体有向上的支持效果，导致底部压力 N₁<G；
  4) 揭示上窄下宽容器侧壁对液体有向下的压力效果，导致底部压力 N₂>G；
  5) 综合得出 N₁<N₂（结论④），并结合匀速运动受力平衡确认 F₁=F₂（结论②），最终四个判断全部正确，答案为 D。
- 教学价值：教师通过分步导航，可先让学生观察容器形状与液面高度，建立密度直觉；再引入压强公式；最后以侧壁压力的竖直分量为突破口，突破"底部压力等于液体重力"的思维定势。图示将抽象的侧壁分力可视化，配合分步回退功能，便于教师根据课堂反应反复讲解难点。

[分步序列]
- 步骤0（初始状态）：显示桌面、左右容器、液体填充、液面对齐线；显示标签 h、ρ₁、ρ₂、P₁、P₂；显示运动标注 v、2v 及拉力 F₁、F₂。此时 P₁、P₂ 为待比较状态，无结论高亮。
- 步骤1（压强比较）：淡入公式卡片 P=ρgh（340,60）；h 标签外加绿色高亮框；ρ₁ 标签变为蓝色高亮，ρ₂ 保持黑色；在两容器之间显示绿色结论文字 "P₁ > P₂ ✓"（400,330）。教师讲解 h 相同、ρ₁>ρ₂，故结论③正确。
- 步骤2（重力参照）：在左右液体中心各出现绿色向下箭头 G（(230,275)→(230,305) 与 (570,275)→(570,305)），标签 G 位于箭头右侧。强调两液体重力相等，作为后续比较基准。
- 步骤3（左侧容器压力分析）：在左侧容器右壁内侧出现侧壁压力合力箭头（黑色，(285,270)→(235,260)），并同步画出灰色水平分量（向左）与蓝色竖直向上分量（向上），以灰色虚线完成矩形分解框；在容器右上方显示说明文字 "侧壁对液体有向上的支持效果"；在左侧底部出现蓝色向上箭头 N₁ 及标签；在左容器下方显示 "N₁ < G"。教师讲解侧壁向上分力托住部分液体重力，故底部压力小于重力。
- 步骤4（右侧容器压力分析）：在右侧容器右壁内侧出现侧壁压力合力箭头（黑色，(605,270)→(555,280)），灰色水平分量（向左）与红色竖直向下分量（向下），灰色虚线矩形框；在容器右上方显示说明文字 "侧壁对液体有向下的压力效果"；在右侧底部出现红色向上箭头 N₂ 及标签；在右容器下方显示 "N₂ > G"。教师讲解侧壁向下分力叠加到重力上，故底部压力大于重力。
- 步骤5（综合结论）：在两容器之间下方显示关系链 "N₁ < G < N₂"（400,375），右侧跟绿色 "✓ N₁ < N₂"；在底部 y=405~435 出现汇总条，四个判断 ①②③④ 均标绿色对勾，最右侧绿色加粗 "答案：D"。教师总结四个判断全部正确。

[交互方案]
- 交互类型：分步按钮导航（◀ 上一步 / 下一步 ▶）
- 控件说明：
  1. 「上一步」按钮：位于 SVG 内底部 (280,454)，80×32 px，点击回退到上一分步。
  2. 「下一步」按钮：位于 SVG 内底部 (440,454)，80×32 px，点击前进到下一分步。
  3. 步骤指示器：位于两按钮之间下方 (400,490)，显示 "步骤 X / 6"。
- 教师操作流程：
  1. 教师加载页面，学生观察步骤0的基础装置（两容器、液体、标注）。
  2. 教师点击「下一步」进入步骤1，讲解 P=ρgh，强调 h 相同而 ρ₁>ρ₂，得出 P₁>P₂。
  3. 点击「下一步」进入步骤2，引入重力 G 作为基准。
  4. 点击「下一步」进入步骤3，聚焦左侧容器，展示侧壁压力分解与向上分量，得出 N₁<G。
  5. 点击「下一步」进入步骤4，聚焦右侧容器，展示侧壁压力分解与向下分量，得出 N₂>G。
  6. 点击「下一步」进入步骤5，呈现关系链 N₁<G<N₂ 与汇总条，确认答案 D。
  7. 教师可随时点击「上一步」回退到任意步骤复习。

[技术实现]
- JS 库选择：原生 SVG + 原生 JavaScript。理由：本场景以静态几何图形、箭头、标签和分组显隐为主，无需复杂数据绑定或 3D，原生 SVG 性能最佳且可控性最高。
- 画布尺寸：800 × 500 px（固定）。
- 布局草图（ASCII）：
  ```
  [图示区 800×500]
  +----------------------------------------------------------+
  |  公式卡片(步骤1)                                          |
  |       v →          h              2v →                   |
  |    +-------+  ~ ~ ~ ~ ~  +-------+                       |
  |   /  ρ₁    \            /  ρ₂    \                      |
  |  /    G↓    \          /    G↓    \                     |
  | |  ←F₁      |        |  ←F₂      |                      |
  |  \          /          \          /                     |
  |   \  N₁↑  /            \  N₂↑  /                        |
  |    +-----+              +-----+                         |
  |   P₁  N₁<G            P₂  N₂>G                         |
  |                                                          |
  |        N₁ < G < N₂   ✓ N₁ < N₂                          |
  |  +--------------------------------------------------+   |
  |  | ①✓  ②✓  ③✓  ④✓        答案：D                |   |  <- 汇总条(步骤5)
  +----------------------------------------------------------+
       [上一步]          步骤 X/6          [下一步]          <- 控件区 y=454~490
  ```
- 关键实现要点：
  1. 状态机设计：使用变量 `currentStep`（0~5），数组 `stepGroups` 存储每步需显示/隐藏的 SVG `<g>` 元素 ID 列表。切换步骤时，遍历所有分组，小于等于 currentStep 的设为 `visibility: visible`，大于的设为 `hidden`（或按显隐逻辑精确控制）。
  2. 箭头绘制：在 `<defs>` 中定义 `<marker>`（id="scene3-arrowhead-black"、"scene3-arrowhead-blue"、"scene3-arrowhead-red"、"scene3-arrowhead-green"、"scene3-arrowhead-gray"），供不同颜色箭头复用。
  3. 坐标计算：液体上表面宽度按线性插值精确计算（左容器 y=220 时 x∈[157.5,302.5]，右容器 y=220 时 x∈[542.5,597.5]），确保液面与侧壁精确相接。
  4. 动画曲线：分步切换不使用复杂动画，直接显隐；如需柔和过渡，可对新增组添加 200ms 的 opacity 渐变（CSS transition）。
  5. 事件绑定：上一步/下一步按钮绑定 click 事件，更新 currentStep 后调用 `renderStep()` 刷新视图。按钮在边界状态禁用（步骤0 时禁用上一步，步骤5 时禁用下一步）。
  6. 公式渲染：P=ρgh 直接使用 Unicode 字符（P=ρgh）放入 `<text>`，无需引入 MathJax，减少依赖。
- ID 命名规范：所有 SVG 元素及控件 ID 必须以 `scene3-` 为前缀。例如：
  - 容器：`scene3-container-left`、`scene3-container-right`
  - 液体：`scene3-liquid-left`、`scene3-liquid-right`
  - 标签：`scene3-label-rho1`、`scene3-label-P1`
  - 步骤分组：`scene3-step1-group`、`scene3-step2-group`、...、`scene3-step5-group`
  - 按钮：`scene3-btn-prev`、`scene3-btn-next`
  - 步骤指示：`scene3-step-indicator`
  - JS 中获取元素严格使用 `document.getElementById`，禁止全局 class 查询，避免多场景合并时跨场景污染。
- IIFE 隔离：所有 JavaScript 逻辑包裹在 `(function() { ... })();` 中，内部变量不泄露全局作用域。
