[技术实现]
- JS 库选择：原生SVG + 原生JavaScript。理由：本场景以静态几何图形和文本标签为主，交互仅为显示/隐藏/样式切换，无需复杂动画或数据驱动绘图，原生SVG最轻量且可控。
- 画布尺寸：800 × 500 px（SVG viewBox="0 0 800 500"）
- 布局草图（ASCII）：
  ```
  [图示区 800×500]
  +----------------------------------------------------------+
  | ○—A原子  4个A₂+1个B₂        2个A₂B+2个A₂                |
  | ●—B原子                                                  |
  |                                                          |
  |   ○—○   ○—○   ○—○      →       ●—○—○     ●—○—○      |
  |   A₂    A₂    A₂                  A₂B       A₂B         |
  |                                                          |
  |   ○—○   ●—●                        ○—○      ○—○        |
  |   A₂    B₂                         A₂       A₂          |
  |                                                          |
  |        反应前                      反应后                 |
  |                                                          |
  |   A．是化合反应                                          |
  |   B．有单质生成                                          |
  |   C．反应前后分子种类不变                                |
  |   D．参加反应的两种分子个数比为4：1                      |
  |                                                          |
  |        [◀ 上一步]   步骤 0/6   [下一步 ▶]               |
  +----------------------------------------------------------+
  ```
- 关键实现要点：
  1. 状态机设计：使用变量`currentStep`（0~6），每步一个渲染函数`renderStep()`，根据`currentStep`值控制所有元素的显示/隐藏/样式。避免为每步单独维护DOM，而是统一在render中按状态设置属性。
  2. 元素分组：将每个分子及其标签放入`<g>`组（如`scene1-mol-a2-1`），便于统一控制显示/隐藏/透明度。未参与反应分子组在步骤1设opacity=0.3，步骤2设display=none，步骤3~6恢复display=block但保持opacity=0.3（或根据需求调整）。
  3. 高亮框实现：使用`<rect>`元素，初始display=none，步骤1时显示并设置stroke颜色（蓝#1565c0或绿#2e7d32）。通过JavaScript动态设置x/y/width/height或预先定义好坐标。
  4. 选项背景高亮：每个选项预先放置一个`<rect>`（如`scene1-opt-a-bg`），初始fill=none或display=none，验证步骤时设置fill=#e8f5e9或#ffebee并显示。
  5. 正误标记：使用`<text>`元素，初始display=none，对应步骤显示。
  6. 步骤6删除线：在选项D文本中使用两个`<tspan>`，第二个tspan包含"4：1"并设置`text-decoration="line-through"`，初始不应用，步骤6时通过JS设置样式。或在"4：1"上方画一条红色line元素。
  7. 动画曲线：本场景无需复杂动画，显示/隐藏使用直接切换（display/opacity属性变化）。如需平滑过渡，可在CSS中定义`.transition { transition: opacity 0.3s ease; }`。
  8. 事件绑定：上一步/下一步按钮绑定click事件，调用`changeStep(delta)`，更新`currentStep`后调用`renderStep()`。
- **ID 命名规范**：所有交互元素ID必须以`scene1-`为前缀。例如：
  - 分子组：`scene1-mol-a2-1` ~ `scene1-mol-a2-6`, `scene1-mol-b2-1`, `scene1-mol-a2b-1` ~ `scene1-mol-a2b-2`
  - 原子：`scene1-atom-a2-1-left`, `scene1-atom-b2-1-right`等
  - 标签：`scene1-label-count-before`, `scene1-label-formula-a2-1`等
  - 选项：`scene1-opt-a`, `scene1-opt-b`, `scene1-opt-c`, `scene1-opt-d`
  - 选项背景：`scene1-opt-a-bg`, `scene1-opt-b-bg`等
  - 按钮：`scene1-btn-prev`, `scene1-btn-next`
  - 步骤指示器：`scene1-step-indicator`
  - 过程框：`scene1-process-box`
  - 正误标记：`scene1-mark-a`, `scene1-mark-b`等
  - JS中严格使用`document.getElementById()`获取元素，禁止用`querySelectorAll`配合全局class，避免多场景合并时跨场景污染。
- IIFE 隔离：所有JavaScript代码包裹在`(function() { ... })();`中，不暴露全局变量。仅内部维护`currentStep`和`renderStep`等局部函数。
