[图示主题与整合说明]
- 本图示主题：固体加热分解质量变化的对比探究（KMnO₄ vs CaCO₃）
- 整合的步骤/概念：将原题中 B 选项（加热 KMnO₄）与 C 选项（高温煅烧 CaCO₃）的固体质量-时间曲线整合到同一坐标系中，通过三状态切换，先分别建立单一反应的正确图像认知，再在对比视图中引入 B 选项的错误曲线（降至零）作为反面参照，帮助学生辨析“固体加热分解后质量不会降为零”这一关键结论。
- 教学价值：教师可先聚焦讲解 KMnO₄ 分解曲线（状态1），再切换讲解 CaCO₃ 煅烧曲线（状态2），最后通过对比模式（状态3）直观呈现两条正确曲线的共性（终点>0）与差异（有无预热平台），并对比 B 选项错误曲线，强化概念辨析。

[分步序列]
本场景为“多状态切换”交互，共 3 个状态，无顺序强制，教师可自由跳转。

- 状态1（KMnO₄分解）——初始状态：
  • 显示元素：坐标系、KMnO₄蓝色曲线及其填充、起点圆点、平台过渡圆点、初始质量辅助线、KMnO₄终了辅助线、m(初始)标签、m(终,KMnO₄)标签

  • 右侧信息：CaCO₃标题（绿）、化学方程式 CaCO₃ 高温 CaO + CO₂↑、预热期说明、反应完全说明、m(最终)=56%m(初始)

  2. 「CaCO₃煅烧」按钮：位置 (340,12)，大小 120×34。点击切换至状态2，显示 CaCO₃ 单一曲线与信息。
  3. 「对比模式」按钮：位置 (480,12)，大小 120×34。点击切换至状态3，显示双曲线+B错误曲线+对比信息。
- 教师操作流程：
  1. 课堂讲解 KMnO₄ 时，点击「KMnO₄分解」，聚焦蓝色曲线，强调“固体质量减少但保持平台、不为零”。
  2. 转而讲解 CaCO₃ 时，点击「CaCO₃煅烧」，聚焦绿色曲线，强调“预热平台→分解下降→稳定平台”的三阶段。
  3. 进行类比辨析时，点击「对比模式」，引导学生观察两曲线共性（终点均>0）与差异（有无预热平台），并指出灰色虚线代表的 B 选项错误（降至零），从而巩固正确图像。

[技术实现]
- JS 库选择：原生 SVG + 原生 JavaScript。理由：本场景为静态折线/曲线的显隐切换，无需复杂数据绑定或 3D 渲染，原生 SVG 足以保证清晰度与性能，且便于教师直接修改坐标。
- 画布尺寸：800 × 500 px（固定）。
- 布局草图：
  ```
  +--------------------------------------------------+
  |          [KMnO₄分解] [CaCO₃煅烧] [对比模式]       |  y=12~46
  |                                                  |
  |   固体质量/g                                      |
  |      ↑    120 ┤                                   |
  |      │    100 ┤  ●─── m(初始)                      |
  |      │     80 ┤  │                                |  左侧
  |      │     60 ┤  │      坐标系绘图区               |  70%
  |      │     40 ┤  │      (x=60~560)                |
  |      │     20 ┤  │                                |
  |      │      0 ┼──┴──┬──┬──┬──┬──┬──→ 反应时间/min |
  |      └────────┘  0  2  4  6  8  10                |
  |                              (x=100~550)          |
  |                          右侧信息区 (x=575~785)   |
  +--------------------------------------------------+
  |              底部留白 y=440~500                   |
  +--------------------------------------------------+
  ```
- 关键实现要点：
  1. 状态机设计：定义 state = 1 | 2 | 3。点击按钮时更新 state，调用 render(state) 函数。
  2. render 函数逻辑：根据 state 设置各 SVG 元素及右侧 div 的 display 属性（或 opacity 过渡）。建议用 CSS transition: opacity 0.3s 实现平滑切换。
  3. 曲线绘制：KMnO₄ 用三次贝塞尔曲线（path 的 C 命令）模拟指数衰减趋近平台；CaCO₃ 用 L 命令绘制折线；B错误用单条 L 直线。
  4. 填充区域：使用 path 闭合到 x轴（y=380）形成填充，注意设置 pointer-events: none 避免遮挡交互。
  5. 按钮激活态：通过 JS 动态添加/移除 active class，active 类设置对应背景色（蓝/绿/灰）与白字。
  6. 事件绑定：每个按钮绑定 onclick，调用 switchScene(n)。
- ID 命名规范：所有交互元素 ID 必须以 `scene2-` 为前缀。例如：
  - 按钮：`scene2-btn-kmno4`、`scene2-btn-caco3`、`scene2-btn-compare`
  - 曲线：`scene2-curve-kmno4`、`scene2-curve-caco3`、`scene2-curve-b-wrong`
  - 辅助线：`scene2-line-init`、`scene2-line-k-final`、`scene2-line-c-final`、`scene2-vline-start`、`scene2-vline-end`
  - 标签：`scene2-label-m-init`、`scene2-label-m-k-final`、`scene2-label-m-c-final`
  - 信息面板：`scene2-info-kmno4`、`scene2-info-caco3`、`scene2-info-compare`
  - 圆点：`scene2-dot-start`、`scene2-dot-k-plat`、`scene2-dot-c-start`、`scene2-dot-c-end`
- IIFE 隔离：所有 JavaScript 代码包裹在 `(function() { ... })();` 中，避免多场景合并时的全局变量污染。
- 容器结构建议：外层 div（position: relative; width: 800px; height: 500px），内部 SVG（width=800 height=500），右侧信息 div（position: absolute; left: 575px; top: 75px; width: 210px），按钮 div（position: absolute; top: 12px; left: 200px; display: flex; gap: 20px）。
