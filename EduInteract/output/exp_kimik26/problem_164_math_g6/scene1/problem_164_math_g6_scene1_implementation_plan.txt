[图示主题与整合说明]
- 本图示主题：三视图特征提取与观察目标建立（小学数学观察物体）
- 整合的步骤/概念：将图1的正面、侧面、上面三个视图按认知顺序拆解——先整体感知三视图布局，再逐一分视图聚焦轮廓特征（正面矩形、侧面上部梯形、上面梯形），最后汇总成"观察目标卡"，为后续与图2三个立体物体进行匹配对比做铺垫。
- 教学价值：教师通过"上一步/下一步"带领学生从全局到局部再汇总，训练"视图→特征→匹配"的空间推理链条；分步高亮避免信息过载，红色专门标记"梯形"这一核心区分特征，强化记忆锚点。

[分步序列]
- 初始状态（步骤0 / 状态0）——整体观察：
  - 三个视图框均以黑色边框2px显示，内部无填充。
  - 各框内图形（正面矩形、侧面矩形+梯形、上面梯形）均以黑色描边2px显示。
  - 各框内十字中心虚线显示（#888888，opacity 0.3），强化"视图"感。
  - 框下方显示"正面""侧面""上面"标签。
  - 无高亮、无步骤标注、无汇总卡。
  - 步骤指示器显示"步骤 1 / 5"。

- 步骤1（状态1）——聚焦正面：
  - 正面视图框边框变为#1565c0，线宽3px；框内整体填充#1565c0，opacity 0.15。
  - 正面框内中心虚线隐藏。
  - 其他两个视图框恢复/保持普通黑色边框2px，无填充。
  - 在正面框正上方显示标注文本"矩形轮廓"。
  - 步骤指示器显示"步骤 2 / 5"。

- 步骤2（状态2）——聚焦侧面：

  - 侧面视图框边框变为#1565c0，线宽3px；无填充。
  - 侧面上部梯形轮廓叠加红色描边#c62828，线宽2px（下部矩形保持黑色）。

- 步骤3（状态3）——聚焦上面：

  - 在上面框正上方显示标注文本"梯形轮廓"。

  - 上面视图框恢复普通状态（黑边框2px，无填充），上面梯形红色填充保留（作为特征提醒），其上方标注隐藏。
  - 三个视图框均保持普通黑色边框，内部特征标记保留（侧面上部梯形红描边、上面梯形红填充）。

[交互方案]
- 交互类型：分步按钮导航（◀ 上一步 / 下一步 ▶）
- 控件说明：
  1. "◀ 上一步"按钮：位置(280,455)，尺寸90×34。在状态0时禁用（opacity 0.4，不响应点击）；其他状态可点击，回退到上一状态。
  2. "下一步 ▶"按钮：位置(430,455)，尺寸90×34。在状态4时禁用（opacity 0.4，不响应点击）；其他状态可点击，前进到下一状态。
  3. 步骤指示器：位置(400,445)，纯文本，显示当前步骤编号"步骤 n / 5"，无点击交互。
- 教师操作流程：
  1. 教师打开图示，学生看到三视图整体布局（步骤0），建立全局印象。
  2. 教师点击"下一步"进入步骤1，正面视图框高亮，教师提问："正面看到什么轮廓？"引导学生回答"矩形"。
  3. 教师点击"下一步"进入步骤2，侧面视图框高亮，上部梯形红描边，教师引导学生观察"侧面与正面有什么不同"。
  4. 教师点击"下一步"进入步骤3，上面视图框高亮，梯形红填充，教师强调"上面也是梯形，这是关键特征"。
  5. 教师点击"下一步"进入步骤4，汇总卡出现，教师带领学生朗读三项特征，为后续对比图2中的①②③做铺垫。
  6. 讲解中可随时点击"上一步"回退到任意视图重新观察。

[技术实现]
- JS库选择：原生 SVG + 原生 JavaScript。理由：本场景为静态几何图形与简单状态切换，无需复杂数据绑定或3D渲染；SVG的DOM操作可直接控制stroke、fill、opacity属性，配合CSS transition实现平滑高亮过渡。
- 画布尺寸：800 × 500 px（固定）。
- 布局草图（ASCII）：
  ```
  0    100  200  300  400  500  600  700  800
  +----+----+----+----+----+----+----+----+----+
  0 |                                          |
  50 |  [矩形轮廓]  [下部矩形+上部梯形] [梯形轮廓] |  ← 步骤标注区（仅对应步骤显示）
  80 |  +----------+  +----------+  +----------+ |
  90 |  |  ┌──┐    |  |    ╱╲    |  |   ╱╲     | |
  110|  |  │  │    |  |   ╱  ╲   |  |  ╱  ╲    | |
  130|  |  │  │    |  |  ╱    ╲  |  | ╱    ╲   | |
  180|  |  │  │    |  | ┌──────┐ |  |└──────┘   | |
  190|  |  │  │    |  | │      │ |  |          | |
  250|  |  │  │    |  | │      │ |  |          | |
  300|  |  └──┘    |  | └──────┘ |  |          | |
  315|  +----------+  +----------+  +----------+ |
  320|    正面         侧面          上面        |
  350|                                          |
  360|  +------------------------------------+   |  ← 汇总卡（仅步骤4）
  390|  |  ●正面:矩形  ●侧面:矩形+梯形  ●上面:梯形 | |
  410|  +------------------------------------+   |
  440|                                          |
  445|           步骤 n / 5                     |
  455|      [◀ 上一步]    [下一步 ▶]            |
  490|                                          |
  500+------------------------------------------+
  ```
- 关键实现要点：
  1. 状态机设计：使用变量 `let state = 0;` 表示5个状态（0~4）。每次点击按钮时 `state++` 或 `state--`，然后调用 `render(state)` 统一更新所有元素的 visibility、stroke、fill、opacity。
  2. 坐标计算：所有SVG元素使用绝对坐标（px），不按比例缩放，确保代码agent直接复用坐标值。
  3. 动画曲线：高亮切换使用CSS transition：`transition: all 0.3s ease;` 应用于视图框的stroke、stroke-width、fill-opacity属性；汇总卡出现使用 `transition: opacity 0.4s ease, transform 0.4s ease;` 从opacity 0 + translateY(10px) 过渡到 opacity 1 + translateY(0)。
  4. 事件绑定：按钮通过 `addEventListener('click', ...)` 绑定；在状态0禁用"上一步"，状态4禁用"下一步"，通过设置 `disabled` 属性并切换CSS类 `.disabled` 实现视觉反馈。
  5. 元素显隐：步骤标注文本和汇总卡使用 `opacity` 切换（而非display:none），以便配合transition动画；中心线组在状态0 opacity=0.3，其他状态 opacity=0。
  6. 汇总卡内绿色圆点：使用文本字符 "●"（U+25CF）或SVG circle(r=4) 实现，颜色#2e7d32。
- ID命名规范（所有交互元素必须以 scene1- 为前缀）：
  - 视图框：scene1-viewbox-front、scene1-viewbox-side、scene1-viewbox-top
  - 框内图形：scene1-shape-front-rect、scene1-shape-side-lower-rect、scene1-shape-side-upper-trap、scene1-shape-top-trap
  - 中心线组：scene1-guide-lines（g元素包裹6条line）
  - 框下标签：scene1-label-front、scene1-label-side、scene1-label-top
  - 步骤标注：scene1-note-front、scene1-note-side、scene1-note-top
  - 汇总卡：scene1-summary-card、scene1-summary-title、scene1-summary-item1、scene1-summary-item2、scene1-summary-item3
  - 控件：scene1-step-indicator、scene1-btn-prev、scene1-btn-next
  - JS中严格使用 `document.getElementById` 获取上述元素，禁止全局class选择，避免多场景合并时跨场景污染。
- IIFE隔离：所有JavaScript代码包裹在 `(function() { ... })();` 中，不暴露全局变量；状态变量 `state` 与 `render` 函数均定义在IIFE内部。
