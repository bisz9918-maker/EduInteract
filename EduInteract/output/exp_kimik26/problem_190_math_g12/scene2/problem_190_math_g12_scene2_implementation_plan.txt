[分步序列]
- 初始状态（步骤0）：显示四棱锥P-ABCD全部棱线（实线/虚线区分）；高亮平面PAB（蓝色半透明填充）和平面PDC（红色半透明填充）；显示顶点标签P,A,B,C,D和平面标签"平面PAB"、"平面PDC"。等待教师触发下一步。
- 步骤1：点击「下一步」→ 新增交线l（绿色粗线，从P到(560,170)）；新增标注"l = 平面PAB ∩ 平面PDC"在(480,110)。教师讲解两平面相交必有过公共点P的交线。
- 步骤2：点击「下一步」→ 新增点Q（绿色圆点，PA中点(285,185)）；新增标签"Q"；新增直线m（绿色，从Q(285,185)到PB上的(367,226)，完全落在平面PAB内）；新增标注"m ⊂ 平面PAB，m ∥ l"在(310,205)。教师讲解在平面PAB内可过Q作m平行于l。
- 步骤3：点击「下一步」→ 新增高亮标注"m ∥ 平面PDC"在(280,420)，字体加粗或颜色改为#c62828；保持m和l的显示。教师讲解：因为m ∥ l且l ⊂ 平面PDC，m ∉ 平面PDC，由线面平行判定定理得m ∥ 平面PDC。
- 步骤4：点击「下一步」→ 在平面PAB内新增3条平行于l的直线（直线族），分布在平面PAB不同位置：线1(204,251)→(344,321)、线2(239,223)→(354,281)、线4(319,156)→(377,185)；单条示例线m保持不透明线宽2px以示区别；新增说明文字"平面PAB内与l平行的直线有无数条，均平行于平面PDC"在(200,415/435)。教师总结：由于平面PAB内与l平行的直线有无数条，且l ⊂ 平面PDC，故这些直线均平行于平面PDC，命题②正确。
- 教师可随时点击「上一步」回退到任意步骤复习。

[交互方案]
- 交互类型：分步按钮导航（◀上一步 / 下一步▶）
- 控件说明：
  - 「上一步」按钮：位置(300,455)，宽80px高30px，点击回退到上一状态，步骤0时禁用
  - 「下一步」按钮：位置(420,455)，宽80px高30px，点击前进到下一状态，步骤4时禁用
  - 步骤指示器：位置(400,448)，显示当前步骤编号（如"步骤 2 / 5"）
- 教师操作流程：
  1. 教师展示步骤0，让学生观察四棱锥及两个高亮平面PAB、PDC
  2. 点击「下一步」进入步骤1，引出交线l，说明两平面相交有交线
  3. 点击「下一步」进入步骤2，在平面PAB内构造m∥l，建立具体例子
  4. 点击「下一步」进入步骤3，高亮m∥平面PDC，应用判定定理
  5. 点击「下一步」进入步骤4，展示无数条平行线，完成"特殊→一般"的升华
  6. 可随时回退复习关键步骤

[技术实现]
- JS库选择：原生SVG + 原生JavaScript（无需外部库，简单几何场景原生SVG性能最佳且无需额外CDN依赖）
- 画布尺寸：800 × 500 px（固定）
- 布局草图（ASCII）：
  ```
  +------------------------------------------+  y=0
  |                                          |
  |              P                           |  y=90
  |  平面PAB    /\    平面PDC                |  y=140
  |           /  \  /  \                     |
  |      Q   /    \/    \                    |  y=185
  |         /   l  |      \                  |
  |    A   /       |    D   \    C           |  y=240-360
  |       \    m   |       /                 |
  |        \       |      /                  |
  |         \      |     /                   |
  |          B-----+----                     |  y=380
  |                                          |
  |    [上一步]  步骤 2/5  [下一步]          |  y=455
  +------------------------------------------+  y=500
  ```
- 关键实现要点：
  1. 状态机设计：用变量 `currentStep`（0~4）记录当前步骤。初始化时只显示步骤0元素，其余通过CSS `display:none` 或 `visibility:hidden` 隐藏。
  2. 元素分组：将各步骤新增元素分别包裹在 `<g id="scene2-step1">`、`<g id="scene2-step2">` 等组中，通过切换组的 `display` 属性实现步骤切换。
  3. 按钮状态：在 `updateUI()` 函数中根据 `currentStep` 设置上一步/下一步按钮的 `disabled` 属性，并更新步骤指示器文字。
  4. 坐标计算：所有坐标硬编码于SVG元素中，无需运行时计算（除按钮事件外）。
  5. 动画曲线：本场景无需复杂动画，步骤切换采用即时显示/隐藏（教师课件追求清晰稳定，淡入淡出可选，非必须）。
  6. 事件绑定：上一步/下一步按钮绑定 `click` 事件，调用 `prevStep()` / `nextStep()`。
- **ID命名规范**：所有交互元素ID必须以 `scene2-` 为前缀。例如：
  - SVG根元素：`scene2-svg`
  - 交线l：`scene2-line-l`
  - 示例线m：`scene2-line-m`
  - 点Q：`scene2-point-q`
  - 步骤1组：`scene2-group-step1`
  - 上一步按钮：`scene2-btn-prev`
  - 下一步按钮：`scene2-btn-next`
  - JS中严格使用 `document.getElementById('scene2-xxx')` 获取元素，禁止用 `querySelectorAll` 配合全局class，避免多场景合并时跨场景污染。
- IIFE隔离：所有JavaScript代码包裹在 `(function() { ... })();` 中，变量不污染全局作用域。
- 样式内联：SVG元素使用内联 `style` 或 `stroke`/`fill` 属性，确保单文件可独立运行。
