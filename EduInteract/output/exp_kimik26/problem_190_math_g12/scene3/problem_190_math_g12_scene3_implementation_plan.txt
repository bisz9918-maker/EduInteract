[分步序列]
- 步骤0（初始状态）：显示完整四棱锥P-ABCD（所有棱线及顶点标签P/A/B/C/D）；平面PAB以蓝色半透明填充，平面PDC以红色半透明填充；交线l以绿色粗线显示，带标签l；底面下方标注"底面ABCD"。右侧推理区空白，等待教师讲解起始条件。
- 步骤1（反证法假设）：点击「下一步」→ 在交线l右侧出现灰色虚线双向箭头（(430,155)-(520,155)），暗示平行关系；右侧推理区出现文字"假设：l ∥ 底面ABCD"(620,100)；教师引导学生明确反证法起点。
- 步骤2（推出l∥AB）：点击「下一步」→ AB线段高亮为红色粗线（#c62828, 2.5px）；右侧推理区依次出现："∵ l ⊂ 平面PAB"(620,150)、"且 平面PAB ∩ 底面ABCD = AB"(620,172)、"∴ l ∥ AB"(640,198, 绿色加粗)。教师讲解线面平行性质定理。
- 步骤3（推出l∥DC）：点击「下一步」→ DC线段（原虚线CD）高亮为红色粗线（#c62828, 2.5px）；右侧推理区依次出现："∵ l ⊂ 平面PDC"(620,250)、"且 平面PDC ∩ 底面ABCD = DC"(620,272)、"∴ l ∥ DC"(640,298, 绿色加粗)。教师继续推导。
- 步骤4（矛盾导出）：点击「下一步」→ 底面中央出现红色叉号（(335,315)-(365,345)与(365,315)-(335,345)）；右侧推理区出现："∴ AB ∥ DC"(620,350)、"✗ 与已知矛盾（AB与DC不平行）"(620,380, 红色)。教师指出与题设"两组对边均不平行"冲突。
- 步骤5（结论）：点击「下一步」→ 右侧出现绿色边框结论框(610,400)-(785,455)，内写"故假设不成立，"(620,428)与"交线l与底面ABCD不平行"(620,450)。教师总结命题③正确。

[技术实现]
- JS库选择：原生SVG + 原生JavaScript。原因：本场景为静态几何图形与分步显隐控制，无需复杂动画库或3D渲染，原生SVG即可精确控制各元素层级与样式，保证轻量与兼容性。
- 画布尺寸：800 × 500 px（固定）
- 布局草图（ASCII）：
  ```
  +--------------------------------------------------+
  |                                                  |
  |     P(顶点)                                      |
  |    / | \                                         |
  |   /  |  \        右侧推理链（x=620~780）          |
  |  A   |   D       步骤1: 假设...                   |
  |   \  |  /        步骤2: ∵ l⊂PAB...               |
  |    \ | /         步骤3: ∵ l⊂PDC...               |
  |      B----------C  步骤4: 矛盾！                  |
  |     底面ABCD     步骤5: 结论...                   |
  |                                                  |
  |  [蓝色填充:PAB]  [红色填充:PDC]  [绿色:交线l]      |
  |                                                  |
  +--------------------------------------------------+
  |      [◀上一步]      步骤 1/6      [下一步▶]       |
  +--------------------------------------------------+
  控件栏区域：y=455~490（SVG内绝对定位overlay）
  ```
- 关键实现要点：
  1. 状态机设计：使用变量 `currentStep`（范围0~5），每次按钮点击更新状态后调用 `renderStep()` 统一控制所有元素的显隐。
  2. 元素显隐控制：所有步骤相关元素（假设箭头、假设文字、高亮线、推理文字、叉号、结论框）初始 `display:none` 或 `visibility:hidden`，根据 `currentStep` 值切换。使用 `getElementById` 获取各元素，避免class冲突。
  3. 层级管理：SVG内按以下顺序绘制（从底到顶）：底面虚线 → 侧棱实线/虚线 → 平面PAB填充 → 平面PDC填充 → 平面边界线 → 交线l → AB/DC高亮线 → 顶点标签 → 推理标注 → 矛盾叉号 → 结论框。
  4. 动画曲线：本场景为分步切换，无需连续动画；步骤切换时元素直接显隐即可。若需柔和过渡，可对文字和线条使用CSS transition: opacity 0.2s ease。
  5. 事件绑定：按钮点击事件在IIFE内部绑定，更新currentStep后重新渲染，并更新按钮禁用状态与步骤指示器文本。
  6. 平面填充路径：使用SVG `<polygon>` 或 `<path>`，确保顶点顺序正确（PAB: P→A→B；PDC: P→D→C），填充使用 `fill-opacity="0.2"`。
  7. 虚线高亮：DC高亮对应原CD虚线，高亮时保持 `stroke-dasharray="6,4"` 并改为红色粗线，以维持被遮挡棱线的视觉语义。
- ID命名规范：所有交互元素ID必须以 `scene3-` 为前缀。例如：`scene3-line-l`、`scene3-plane-pab`、`scene3-highlight-ab`、`scene3-text-assume`、`scene3-btn-prev`、`scene3-btn-next`、`scene3-step-indicator`。
- IIFE隔离：所有JavaScript代码包裹在 `(function() { ... })()` 中，避免全局变量污染，确保多场景合并时互不干扰。
