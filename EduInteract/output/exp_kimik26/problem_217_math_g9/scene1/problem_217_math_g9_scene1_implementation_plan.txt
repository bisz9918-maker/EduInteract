[技术实现]
- JS库选择：原生SVG + 原生JavaScript。原因：本场景以静态几何图形和简单状态切换为主，无需复杂数据绑定或3D渲染；原生SVG path可精确控制抛物线曲线；原生JS足以管理状态机和简单动画。
- 画布尺寸：800×500px（固定）
- 布局草图：
  ```
  [图示区 800×500]
  +--------------------------------------------------------+
  |  y=x²-2x-3                                    [结论面板] |
  |    ↑                                                  |
  |  y轴  抛物线(开口向上)      A●───────●B               |
  |    |        ↘    ↗         (-1,0)   (3,0)             |
  |    O───────●───────●─────── x轴                       |
  |           C(0,-3)  顶点(1,-4)                         |
  |                                                       |
  |  [主图区：坐标系+抛物线+标注，占满上部430px]            |
  +--------------------------------------------------------+
  |  [◀ 上一步]    步骤 k/4    [下一步 ▶]                  |  y=445~490
  +--------------------------------------------------------+
  ```

- 关键实现要点：
  1. 状态机设计：用变量 `currentStep` ∈ {0,1,2,3,4}，每次按钮点击更新状态，调用 `renderStep()` 函数。`renderStep()` 根据当前步骤设置各元素组的 `display` 或 `visibility` 属性。
  2. 元素分组：将每步骤新增元素包裹在 `<g id="scene1-step1-group">` 等组中，通过控制组的 `style.display` 实现批量显隐。
  3. 抛物线路径：用SVG `<path>` 的 `L` 命令连接9个采样点。采样坐标预先计算好写入path的d属性。
  4. 坐标转换函数：提供 `toSVGx(x)` 和 `toSVGy(y)` 函数，便于后续维护：
     - `toSVGx(x) = 305 + x * 75`
     - `toSVGy(y) = 280 - y * 20`（注意y轴向上为正，SVG向下为正）
  5. 动画曲线：
     - 步骤切换时，新增元素使用CSS `opacity` 过渡（0→1，duration 300ms）实现淡入。
     - 步骤4动点P动画使用 `requestAnimationFrame`，参数t从1到5（x坐标），计算y=(t-1)²-4，映射到SVG坐标，每帧更新 `<circle>` 的cx/cy属性。动画周期2秒，循环播放。
  6. 结论面板状态：每个结论项用一个 `<text>` 元素，步骤切换时修改其 `fill` 颜色（#888→#2e7d32）并在左侧添加/显示勾号 `<path>` 或 `✓` 字符。
  7. 按钮状态：步骤0时「上一步」禁用（opacity 0.4, pointer-events none）；步骤4时「下一步」禁用。
  8. 事件绑定：按钮绑定 `click` 事件，在IIFE内部处理，避免全局污染。

- ID命名规范：
  - 所有SVG元素ID必须以 `scene1-` 为前缀。
