[图示主题与整合说明]
- 本图示主题：选项验证与反应类型判断（化学九年级·物质转化与反应类型）
- 整合内容：A/B 选项快速排除、C 选项置换反应陷阱分析、D 选项复分解反应验证、最终结论
- 教学价值：教师通过分步导航，逐一聚焦四个选项的验证过程；C 选项通过三个方程式的并列对比，直观揭示"置换反应必须是单质+化合物"的判定标准；D 选项通过在关系图三条边上同步弹出方程式，建立"两两反应"与"复分解"的强关联。

[分步序列]
- 步骤0（初始状态）：
  • 关系图：X 显示"氢氧化钙/碳酸钠"，Y 显示"稀盐酸"，M 显示"碳酸钠/氢氧化钙"，N 显示"N"，铁 显示"铁"；所有连线黑色 2px。
  • 选项卡片：A/B/C/D 均为未激活状态（白底黑框）。
  • 分析区：显示引导文字"请依次点击「下一步」验证各选项"，居中，灰色。
  • 按钮：「上一步」禁用（opacity 0.4），「下一步」可用。

- 步骤1（验证 A 选项）：
  • 选项A卡片：红高亮（边框#c62828，填充rgba(198,40,40,0.10)），其余卡片边框变为#888888（辅助线色）。
  • 关系图：X 节点内文字在"氢氧化钙"与"碳酸钠"之间切换动画（每 500ms 切换一次，共 3 次，持续 1.5s），提示 X 不唯一。
  • 分析区：显示两行文本——第一行"X 可能是氢氧化钙，也可能是碳酸钠"；第二行"因此 X 不唯一确定"；右侧配红色✗标记。

- 步骤2（验证 B 选项）：
  • 选项A卡片：恢复为未激活（白底+#888888边框）。
  • 选项B卡片：红高亮。
  • 关系图：Y 节点边框变为蓝高亮#1565c0（3px），强调 Y 是稀盐酸；在 Y 节点右下方(460,110)弹出对比标签"稀盐酸 ✓"（绿色）和"氢氧化钙 ✗"（红色，带删除线），持续 2s 后消失。
  • 分析区：显示"Y 能与铁、氧化铁反应，符合稀盐酸的性质"；第二行"Y 是稀盐酸，不是氢氧化钙"；右侧配红色✗标记。

- 步骤3（验证 C 选项）：
  • 选项B卡片：恢复未激活。
  • 选项C卡片：红高亮。
  • 关系图：N 节点文字变为"氧化铁"，N 节点边框红高亮#c62828；N→铁 连线变为红色 3px。
  • 分析区：标题"N（氧化铁）转化为铁的反应："(50,295)。三行方程式纵向排列，行高 35px：
    - 行1 y=325："3H₂ + Fe₂O₃ → 2Fe + 3H₂O" + 绿色"置换反应 ✓"
    - 行2 y=360："2Al + Fe₂O₃ → 2Fe + Al₂O₃" + 绿色"置换反应 ✓"
    - 行3 y=395："3CO + Fe₂O₃ → 2Fe + 3CO₂" + 红色"不是置换反应 ✗"
    - 提示 y=425：红色文字"注意：CO 是化合物，该反应不属于置换反应"

- 步骤4（验证 D 选项）：
  • 选项C卡片：恢复未激活。
  • 选项D卡片：绿高亮（边框#2e7d32，填充rgba(46,125,50,0.12)）。
  • 关系图：X-Y、Y-M、X-M 三条连线变为绿色 3px（transition 0.3s）；X 节点文字固定为"氢氧化钙"，M 节点文字固定为"碳酸钠"（代表一种合理排列）。
  • 分析区：标题"X、Y、M 两两之间的反应："(50,295)。三行方程式：
    - 行1 y=330："X—Y：Ca(OH)₂ + 2HCl → CaCl₂ + 2H₂O" + 绿色"复分解 ✓"
    - 行2 y=365："Y—M：2HCl + Na₂CO₃ → 2NaCl + H₂O + CO₂↑" + 绿色"复分解 ✓"
    - 行3 y=400："X—M：Ca(OH)₂ + Na₂CO₃ → CaCO₃↓ + 2NaOH" + 绿色"复分解 ✓"

- 步骤5（结论）：
  • 选项D卡片：保持绿高亮。
  • 选项A/B/C卡片：透明度降至 0.35，边框#888888，文字灰色。
  • 关系图：X-Y-M 三条绿线保持，其余连线淡化（opacity 0.3）。
  • 分析区：清空方程式，居中显示大号文字"正确答案：D"（字号 24px，颜色#2e7d32）；第二行"X、Y、M 两两之间都可以发生复分解反应"（字号 16px，颜色#333）。
  • 按钮：「下一步」禁用，「上一步」可用。

[交互方案]
- 交互类型：分步按钮导航（◀上一步 / 下一步▶）
- 控件说明：
  1. 「◀ 上一步」按钮：位置(280,449)，尺寸100×32。点击回退到上一步骤，步骤0 时禁用。
  2. 「下一步 ▶」按钮：位置(420,449)，尺寸100×32。点击前进到下一步，步骤5 时禁用。
  3. 步骤指示器：位置(400,440)，显示当前步骤编号（如"步骤 2/5"）。
- 教师操作流程：
  1. 教师展示步骤0，说明题目背景与五种物质。
  2. 点击「下一步」进入步骤1，聚焦 A 选项错误原因（X 不唯一）。
  3. 继续点击「下一步」依次展开 B、C、D 的验证；在 C 选项停留时，可引导学生判断三个反应的类型；在 D 选项停留时，可引导学生逐一读出三条边上的复分解方程式。
  4. 到达步骤5后，可点击「上一步」回退到任意步骤复习。

[技术实现]
- JS 库选择：原生 SVG（关系图节点、连线、箭头 marker）+ 原生 HTML/CSS/JS（选项卡片、分析区、按钮）。不引入外部重型库，化学下标用 HTML <sub> 标签即可精确控制。
- 画布尺寸：800 × 500 px（固定）。
- 布局草图（ASCII）：
  ```
  [图示区 800×500]
  +--------------------------------------------------+
  |  关系图区 (y=30~190)                              |
  |    [氢氧化钙/碳酸钠]——[稀盐酸]——[铁]              |
  |         \          /         \          ↑         |
  |          \        /           \        /          |
  |        [碳酸钠/氢氧化钙]    [N/氧化铁]            |
  |                                                   |
  |  选项区 (y=185~265)                               |
  |  [ A ]  [ B ]  [ C ]  [ D ]                       |
  |                                                   |
  |  分析区 (y=280~430)                               |
  |  动态方程式 / 结论文本                              |
  |                                                   |
  |  控件区 (y=445~485)                               |
  |       [◀ 上一步]  [下一步 ▶]                      |
  +--------------------------------------------------+
  ```
- 关键实现要点：
  1. 状态机设计：变量 `currentStep`（0~5），`renderStep(step)` 函数统一根据状态更新所有元素的 class/属性。避免分散的状态修改。
  2. 坐标计算：所有 SVG 元素使用绝对坐标（px），HTML 叠加层使用 `position:absolute` 与 SVG 精确对齐。
  3. 动画曲线：
     - X 节点文字切换：JS setInterval 每 500ms 修改 textContent，3 次后停止。
     - 连线颜色/粗细变化：CSS `transition: stroke 0.3s ease, stroke-width 0.3s ease, opacity 0.3s ease`。
     - 选项卡片高亮：CSS `transition: border-color 0.3s, background-color 0.3s`。
  4. 事件绑定：按钮点击事件在 IIFE 内部绑定，更新 `currentStep` 后调用 `renderStep`。
  5. 化学方程式渲染：分析区使用 HTML 字符串模板，含 <sub> 标签，直接插入 innerHTML。
  6. 箭头实现：SVG `<defs><marker id="scene2-arrow" ...>`，在 N→铁 line 上设置 `marker-end="url(#scene2-arrow)"`。
- ID 命名规范：所有交互元素 ID 必须以 `scene2-` 为前缀。例如：`scene2-node-x`、`scene2-node-y`、`scene2-line-xy`、`scene2-card-a`、`scene2-analysis`、`scene2-btn-prev`、`scene2-btn-next`。
- IIFE 隔离：所有 JS 逻辑包在 `(function() { ... })()` 中，避免多场景合并时变量污染。
