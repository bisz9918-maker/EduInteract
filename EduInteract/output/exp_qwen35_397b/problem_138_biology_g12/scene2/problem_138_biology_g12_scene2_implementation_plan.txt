[技术实现]
- JS 库选择：原生 SVG + 原生 JavaScript
  - 原因：遗传图解以静态几何图形和文字为主，无需复杂动画；原生 SVG 代码简洁、性能好、易于多场景合并
- 画布尺寸：800 × 500 px（固定）
- 布局草图（ASCII）：
  ```
  [图示区 800×500]
  ┌─────────────────────────────────────────────────────────────┐
  │ P  [植株甲 aa bb ♀]        ×        [植株乙 AA BB ♂]       │ y=30-110
  │                                                                 │
  │         ↓ ab                    ↓ AB                          │ y=110-160
  │                    ↘        ↙                                 │
  │              [F1: Aa Bb 绿豆荚黄子叶]                         │ y=170-240
  │                          ⊗                                    │ y=240-270
  │                    ┌─────────────┐    [答案框 1]              │ y=280-320
  │                    │  4×4 棋盘格  │    [答案框 2]              │ y=320-420
  │                    └─────────────┘                             │
  │                                                                 │
  │              [◀ 上一步]  步骤 X/5  [下一步 ▶]                  │ y=440-500
  └─────────────────────────────────────────────────────────────┘
  ```
- 关键实现要点：
  1. 状态机设计：用 currentStep 变量 (0-4) 跟踪当前步骤，steps 数组存储每步显示的元素 ID 列表
  2. 元素分组：每个视觉元素用<g>分组，ID 格式 scene2-xxx，初始 display:none，按步骤切换 display:block
  3. 棋盘格生成：用循环生成 4×4 网格，单元格基因型用二维数组预定义
  4. 按钮事件：上一步/下一步按钮绑定 click 事件，更新 currentStep 并刷新显示状态
  5. 边界处理：步骤 0 时禁用上一步按钮，步骤 4 时禁用下一步按钮（opacity:0.5）
- ID 命名规范：所有元素 ID 以 scene2- 为前缀
  - scene2-parent-a, scene2-parent-b（亲本框）
  - scene2-gamete-a, scene2-gamete-b（配子）
  - scene2-f1-box, scene2-f1-genotype, scene2-f1-phenotype（F1 代）
  - scene2-punnett-grid, scene2-punnett-cells（棋盘格）
  - scene2-answer1, scene2-answer2（答案框）
  - scene2-btn-prev, scene2-btn-next, scene2-step-indicator（控件）
- IIFE 隔离：所有 JS 代码包在 (function() { ... })() 中，避免全局变量污染
