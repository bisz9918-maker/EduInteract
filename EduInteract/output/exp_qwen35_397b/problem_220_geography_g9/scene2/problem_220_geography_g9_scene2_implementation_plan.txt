[分步序列]
- 初始状态（步骤 0）：显示基础环流框架
  - 显示：矩形环流圈（a-b-c-d 四点及连线）、箭头①②③④、点标签 a/b/c/d、箭头标签①②③④
  - 隐藏：纬度标注、气压带标注、冷暖气流箭头、成因说明框
  - 视觉：黑色线条绘制完整环流圈，等待教师触发下一步

- 步骤 1：标注纬度位置和气压带
  - 新增显示：30°N 标注 (200,395)、60°N 标注 (600,395)
  - 新增显示：副热带高压带文本框 (200,415)、副极地低压带文本框 (600,415)
  - 视觉变化：纬度标注淡入，气压带文本框从下方滑入
  - 教学点：明确 a 处约 30°N（副热带），b 处约 60°N（副极地）

- 步骤 2：显示 b 处冷暖气流相遇
  - 新增显示：暖气流箭头（红色#1565c0，从 (550,350) 指向 (600,330)）
  - 新增显示：冷气流箭头（蓝色#c62828，从 (650,330) 指向 (600,330)）
  - 新增显示：暖空气抬升曲线箭头（红色，从 (600,330) 向上至 (600,250)）
  - 新增显示：冷暖气流相遇标签 (680,300)
  - 视觉变化：冷暖气流箭头从两侧滑入，在 b 处汇合后抬升
  - 教学点：b 处（60°N 副极地低压带）是冷暖气流相遇处，暖空气被迫抬升形成低压

- 步骤 3：显示④处动力原因下沉
  - 新增显示：动力原因框 (680,180)，内容"④处：高空空气堆积→动力原因下沉"
  - 高亮：下沉气流④箭头变为绿色#2e7d32
  - 视觉变化：说明框从右侧滑入，④箭头颜色变化
  - 教学点：④处（30°N 副热带高压带）下沉气流是动力原因（高空空气堆积下沉），非热力原因

- 步骤 4：对比展示热力原因 vs 动力原因
  - 新增显示：成因对比框 (680,100)
    - 内容："热力原因：温度差异引起（如赤道低压、极地高压）"
    - 内容："动力原因：气流运动引起（如副热带高压、副极地低压）"
  - 视觉变化：对比框从上方滑入
  - 教学点：区分两种成因机制，帮助学生理解选项 D 错误（④是动力原因，非热力原因）

- 结论（步骤 5）：验证选项 C 和 D
  - 新增显示：选项验证框 (50,460)
    - "选项 C：✓ 正确 — b 处（60°N）有冷暖气流相遇（来自低纬的暖湿气流与来自高纬的冷干气流）"
    - "选项 D：✗ 错误 — ④处下沉气流是动力原因，非热力原因"
  - 高亮：选项 C 用绿色#2e7d32 标识，选项 D 用红色#c62828 标识
  - 教学点：总结本题正确答案为 C

[技术实现]
- JS 库选择：原生 SVG + 原生 JavaScript
  - 原因：几何图形简单（矩形、箭头、文本），无需复杂库；原生 SVG 便于精确控制坐标和动画
- 画布尺寸：800 × 500 px（固定）
- 布局草图（ASCII）：
  ```
  [图示区 800×500]
  +--------------------------------------------------+
  |                                                  |
  |   d ●───────────────● c     [成因对比]           |
  |     │               │       [动力原因]           |
  |   ④│               │②      [冷暖气流相遇]       |
  |     │               │                            |
  |     ●───────────────●                            |
  |     a               b                            |
  |   30°N            60°N                           |
  |  [副热带]        [副极地]                        |
  |                                                  |
  |                                                  |
  |  [状态指示器]              [◀上一步] [下一步▶]   |
  +--------------------------------------------------+
  ```
- 关键实现要点：
  1. 状态机设计：使用 currentState 变量（0-5），steps 数组存储每步的显示/隐藏元素 ID 列表
  2. 坐标计算：所有元素使用绝对坐标（见布局坐标表），箭头使用 SVG <marker> 定义箭头样式
  3. 动画曲线：使用 CSS transition 实现淡入效果（opacity: 0→1, duration: 0.5s）
  4. 事件绑定：按钮点击事件绑定到 updateState() 函数，根据 currentState 切换元素显示状态
  5. 元素初始化：所有步骤专属元素初始 display:none，步骤 0 仅显示基础框架
- ID 命名规范：所有交互元素 ID 必须以 scene2- 为前缀
  - 示例：scene2-point-a, scene2-point-b, scene2-arrow-1, scene2-label-30N, scene2-btn-prev, scene2-btn-next
- IIFE 隔离：所有 JS 代码包在 (function() { ... })() 中，避免全局变量污染
