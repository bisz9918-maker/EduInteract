[图示主题与整合说明]
- 本图示主题：血液流经不同器官时的成分变化动态演示
- 整合的步骤/概念：整合了原图模型以及选项A、B、C、D四种不同器官（心脏、肺、小肠、组织细胞）的血液流经情况对比。
- 教学价值：教师可以通过分步演示，清晰地向学生展示血液流经不同器官时，血管名称的变化以及血液成分（含氧量，即动静脉血）的改变，帮助学生直观理解并逐一排除错误选项，最终得出正确答案。

[视觉元素清单]
- 基础管道模型：由左右直管和中间圆弧组成的连续轮廓，黑色 #000000，线宽 2px。
- 填充区域：分为 a、b、c 三个独立区域，用于动态改变颜色。透明度统一为 30%。
- 渐变定义：
  - `grad-mixed`：上下线性渐变，0-50%为红色 #c62828，50-100%为蓝色 #1565c0（表示混合或不确定）。
  - `grad-blue-red`：左右线性渐变，0%为蓝色 #1565c0，100%为红色 #c62828（表示静脉血变动脉血）。
  - `grad-red-blue`：左右线性渐变，0%为红色 #c62828，100%为蓝色 #1565c0（表示动脉血变静脉血）。
- 动态文本：包括标题、器官名称、血管名称、血液类型，根据步骤动态更新内容和颜色。
- 判定符号：显示“×”（红色 #c62828）或“√”（绿色 #2e7d32）。

[分步序列]
- 初始状态（步骤0）：
  - 标题：“血液流经某器官的示意图”
  - 管道填充：无（透明）
  - 动态文本：均为空
  - 判定结果：空
- 步骤1（选项A-心脏）：
  - 标题：“选项A：若b为心脏”
  - 管道填充：a、b、c 区域均填充 `url(#grad-mixed)`
  - 动态文本：器官b显示“心脏”；血管a显示“静脉”，血液a显示“静脉血 或 动脉血”；血管c显示“动脉”，血液c显示“静脉血 或 动脉血”
  - 判定结果：“×”（红色）
- 步骤2（选项B-肺）：
  - 标题：“选项B：若b为肺”
  - 管道填充：a区域填充蓝色 #1565c0，b区域填充 `url(#grad-blue-red)`，c区域填充红色 #c62828
  - 动态文本：器官b显示“肺 (肺泡毛细血管)”；血管a显示“肺动脉”，血液a显示“静脉血”（蓝色）；血管c显示“肺静脉”，血液c显示“动脉血”（红色）
  - 判定结果：“×”（红色）
- 步骤3（选项C-小肠）：
  - 标题：“选项C：若b为小肠”
  - 管道填充：a区域填充红色 #c62828，b区域填充 `url(#grad-red-blue)`，c区域填充蓝色 #1565c0
  - 动态文本：器官b显示“小肠 (毛细血管)”；血管a显示“肠动脉”，血液a显示“动脉血”（红色）；血管c显示“肠静脉”，血液c显示“静脉血”（蓝色）
  - 判定结果：“×”（红色）
- 步骤4（选项D-组织细胞）：
  - 标题：“选项D：若b为组织细胞”
  - 管道填充：a区域填充红色 #c62828，b区域填充 `url(#grad-red-blue)`，c区域填充蓝色 #1565c0
  - 动态文本：器官b显示“组织细胞”；血管a显示“体动脉”，血液a显示“动脉血”（红色）；血管c显示“体静脉”，血液c显示“静脉血”（蓝色）
  - 判定结果：“√”（绿色）

[交互方案]
- 交互类型：分步按钮导航（◀上一步 / 下一步▶）
- 控件说明：在 SVG 容器内部底部（y=450 区域）放置两个按钮，用于切换步骤（0~4）。
- 教师操作流程：教师首先展示原图（步骤0），然后点击“下一步”依次展示选项A、B、C、D的血液流经情况。每展示一个选项，图示会自动高亮对应的动静脉血颜色，并显示判定结果，教师可据此讲解判断理由。

[技术实现]
- JS 库选择及原因：原生 SVG。图形主要由简单的线段、圆弧和多边形构成，原生 SVG 能够完美实现，且方便通过 DOM 操作修改填充颜色和文本内容。
- 画布尺寸：800 × 500 px
- 布局草图：
  ```
  [图示区 800×500]
    (标题区)
    a        b        c
  ====>===(     )===>====
    (动态文本区)
                 (判定结果)
  [控件栏 ◀上一步  下一步▶]
  ```
- 关键实现要点：
  - 使用 `<path>` 绘制管道的上下轮廓，确保线条连续且平滑。
  - 使用独立的 `<polygon>` 和 `<path>` 绘制 a、b、c 三个填充区域，置于轮廓底层，通过修改 `fill` 属性实现颜色切换。
  - 预定义 `<linearGradient>` 渐变，用于表示血液在器官中的成分变化过程。
  - 状态机设计：定义一个包含 5 个状态（0-4）的数组，每个状态对象包含该步骤所需的所有文本内容、颜色值和判定结果。点击按钮时更新当前索引，并重新渲染 DOM 元素的属性。
  - ID 命名规范：所有交互元素 ID 必须以 `scene1-` 为前缀（如 `scene1-title`, `scene1-fill-a` 等）。
  - IIFE 隔离：所有 JS 代码封装在 `(function() { ... })()` 中，避免全局变量污染。
