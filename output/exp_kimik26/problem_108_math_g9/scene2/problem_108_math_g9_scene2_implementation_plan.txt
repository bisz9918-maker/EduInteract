[图示主题与整合说明]
- 本图示主题：α+β=180°特殊情形下的延长线构造与选项B、D辨析
- 整合的步骤/概念：
  1) 在α+β=180°条件下展示基础图形，标注∠MCN=120°与x+y=60°；
  2) 通过高亮∠AMB与∠NMB（均等于x），揭示选项B结论恒真、条件多余；
  3) 构造延长线MA与NB的交点O，形成△OMN，推导∠MON=60°；
  4) 以反例（α=80°,β=100°）精确计算OA≠OB，再切回α=β=90°特例说明OA=OB仅为巧合，从而判定选项D不正确。
- 教学价值：教师通过分步导航，先建立"B为真"的信心，再通过构造性作图和数值反例"击破"D的一般性，形成"先立后破"的课堂节奏。学生可直观看到同一图形框架下，特例与反例的数值差异。

[分步序列]

步骤0（初始状态）——展示α+β=180°基础条件：
- 显示元素：MN、AM、AN、BM、BN、点A/B/C/M/N、标签α/β、弧线∠ANM(y)/∠BNA(y)/∠MCN(120°)
- 右侧信息："α+β=180°"、"∠MCN=120°"、"x+y=60°"
- 所有元素主线黑色，无高亮
- 等待教师点击「下一步」

步骤1——选项B辨析（∠AMB与∠NMB恒等）：
- 新增：弧线∠BMN(x)、弧线∠AMB(x)，两个角均标注"x"
- 高亮：BM线段加粗至3px（stroke-width=3），颜色保持黑色或改为#1565c0以突出角平分线
- 右侧信息更新为："∠AMB = ∠NMB = x"（黑色）、"BM平分∠AMN"（黑色）、下方绿色文本"选项B：恒真命题 ✓"
- 视觉焦点：M点附近两个x角标记，引导学生发现二者由同一条角平分线BM自然产生，与α+β无关
- 教师讲解：条件"α+β=180°"多余，结论恒成立

步骤2——构造延长线交点O与△OMN：
- 新增：
  * 虚线OM（从O经过A到M）
  * 虚线ON（从O经过B到N）
  * 点O及标签
  * 弧线∠OMN(2x)、弧线∠ONM(2y)、弧线∠MON(60°)
  * △OMN淡绿填充（polygon O-M-N）
- 右侧信息更新为："延长MA、NB交于O"、"∠OMN=2x, ∠ONM=2y"、"∠MON=180°-2(x+y)=60°"
- 视觉变化：原图上方出现大三角形覆盖，O点居中上方，形成清晰的△OMN框架
- 教师讲解：利用x+y=60°推导∠MON=60°，为步骤3的D选项分析铺垫

步骤3——选项D反例与特例切换（默认先展示反例）：
- 反例视图（默认）：
  * 高亮OA线段（蓝色#1565c0，3px）、OB线段（红色#c62828，3px）
  * 标注OA（蓝色，左侧）、OB（红色，右侧）
  * 右侧信息："反例：α=80°, β=100°"、"x=40°, y=20°"、"OA≈0.395MN"、"OB≈0.484MN"、橙色大字"OA≠OB"、橙色"选项D不正确 ✗"
  * 视觉焦点：OA与OB的蓝色/红色对比，右侧数值不等
- 特例视图（点击「切换视角」后）：
  * OA和OB均变为绿色#2e7d32（3px）
  * 右侧信息："特例：α=β=90°"、"x=y=30°"、绿色"OA=OB=0.5MN"、"仅为巧合，不具一般性"
  * 视觉焦点：绿色等长标记，与反例形成鲜明对比
- 教师讲解：先展示反例击破"OA=OB恒成立"的错觉，再切回特例说明即使有时相等也只是巧合，最终确认D不正确

[技术实现]
- JS库选择：原生SVG + 原生JavaScript。原因：本场景为纯2D几何图形，无复杂函数绘图或3D需求，原生SVG足以精确控制所有线段、点、弧线和文本的位置与显隐，且无需引入外部CDN依赖，加载最快。
- 画布尺寸：800 × 500 px（固定）
- 布局草图：
  ```
  [图示区 800×500]
  +--------------------------------------------------+
  |  标题（居中顶部）                                  |
  |                                                  |
  |        O(400,54)                                  |
  |       /  \                                        |
  |      /    \                                       |
  |     A      B      [右侧信息面板]                  |
  |      \    /       α+β=180°                        |
  |       \  /        ∠MCN=120°                       |
  |        C          x+y=60°                         |
  |       /  \                                        |
  |      /    \                                       |
  |     M------N                                      |
  |  (200,400)(600,400)                               |
  |                                                  |
  |        [◀上一步] [步骤 2/4] [下一步▶]             |
  +--------------------------------------------------+
  控件栏在y=440~490区域
  ```
- 关键实现要点：
  1) 状态机设计：用变量currentStep（0~3）和currentView（"counterexample"/"special"，仅在step3有效）控制显示。每一步对应一个render函数，先清空所有动态元素，再按当前状态重绘。
  2) 元素显隐：使用SVG的display属性或CSS opacity过渡（transition: opacity 0.3s）实现平滑出现/消失。步骤切换时，旧元素淡出，新元素淡入。
  3) 坐标计算：所有坐标硬编码于配置对象const CONFIG中，避免运行时计算误差。弧线使用SVG path的A指令绘制。
  4) 动画曲线：元素出现使用ease-out，持续时间300ms。高亮（如OA/OB加粗）使用stroke-width过渡。
  5) 事件绑定：按钮绑定click事件，更新状态机后调用render()。
  6) 步骤3双状态：在render()中检查if(currentStep===3)，根据currentView决定渲染反例或特例元素。切换时仅更新差异部分（OA/OB颜色、右侧文本），保持O、M、N等基础元素不动。
  7) 信息面板文本：使用tspan或分组g控制每行文本，便于按步骤替换内容。
- ID命名规范：
  * 点：scene2-point-o, scene2-point-a, ...
  * 线段：scene2-line-mn, scene2-line-oa, ...
  * 标签：scene2-label-o, scene2-label-alpha, ...
  * 弧线：scene2-arc-bmn, scene2-arc-omn, ...
  * 按钮：scene2-btn-prev, scene2-btn-next, scene2-btn-toggle
  * 信息面板：scene2-info-panel, scene2-info-line1, ...
  * 填充：scene2-fill-omn
- IIFE隔离：所有JavaScript代码包裹在 (function() { ... })() 中，避免全局命名空间污染，确保多场景合并时互不干扰。
- 响应式说明：容器固定800×500，不随窗口缩放，保证坐标精确性。如需嵌入不同尺寸容器，由外层CSS控制transform: scale()。
