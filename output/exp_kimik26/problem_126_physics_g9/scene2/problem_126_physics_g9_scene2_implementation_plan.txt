[图示主题与整合说明]
- 本图示主题：水平滑轮组的有用功、总功、功率及机械效率计算
- 整合的步骤/概念：装置认知 → 有用功判定（W有=fS）→ 总功计算（W总=3FS）→ 功率推导（P=3Fυ）→ 机械效率（η=f/3F）→ 选项正误判断
- 教学价值：教师通过左侧装置图与右侧公式推导的联动高亮，分步揭示"为什么A选项错误"以及B/C/D正确的完整推导链。左侧视觉强化受力与位移关系，右侧公式区提供严格数学表达，适合课堂逐步讲解。

[分步序列]
- 步骤0（初始状态）：显示完整装置图（桌面、物体A、滑轮组、墙壁、三段绳子、F箭头）。标注已知量：A、f、G、F、S（黑色/灰色）。右侧公式区仅显示区标题"公式推导"，其余空白。n=3 标注始终显示。
- 步骤1（有用功分析）：f箭头与S箭头高亮为红色 #c62828；右侧出现公式 "W有 = f·S = fS"（红色）。G箭头及标签淡化为灰色 #aaaaaa；在G箭头旁出现直角符号，在G标签右侧出现灰色文字 "WG = 0"，直观说明重力不做功，为后续判定A选项错误做铺垫。
- 步骤2（总功分析）：F箭头高亮为蓝色 #1565c0；在F箭头上方出现蓝色双向箭头 "3S"（绳端位移）。右侧出现公式 "W总 = F·3S = 3FS"（蓝色）。步骤1中的W有公式保持显示但可适度淡化（opacity 0.6）。
- 步骤3（功率分析）：物体A上方S标注替换为υ（蓝色），F下方出现 "3υ"（蓝色，表绳端速度）。右侧出现功率公式两行 "P = W总/t = 3FS/t" 与 "= F·3υ = 3Fυ"（蓝色）。步骤2的W总公式可适度淡化。
- 步骤4（机械效率）：右侧出现效率公式第一行 "η = W有/W总 = fS/3FS"（黑色），并在S上方绘制灰色虚线约分线；随后第二行出现 "= f/3F"（绿色 #2e7d32，加粗高亮）。左侧装置图无新增高亮，保持步骤3状态。
- 步骤5（选项判断）：右侧公式可保留但整体淡化（opacity 0.5）。出现2×2选项卡片：A卡片红底红框+删除线+红叉；B/C/D卡片绿底绿框+绿对勾。完成最终判断。

[交互方案]
- 交互类型：分步按钮导航（◀上一步 / 下一步▶）+ 重置
- 控件说明：
  - 「上一步」按钮：位于 (240, 455)，宽80高30。点击回退一个步骤，步骤0时禁用（opacity 0.4）。
  - 「下一步」按钮：位于 (480, 455)，宽80高30。点击前进一个步骤，步骤5时禁用。
  - 「重置」按钮：位于 (600, 455)，宽60高30。点击立即回到步骤0。
  - 步骤指示器：位于 (400, 475)，显示 "步骤 X / 5"（X 为当前步骤号 0~5）。
- 教师操作流程：
  1. 教师展示步骤0，让学生观察装置并识别已知量。
  2. 点击「下一步」进入步骤1，讲解"有用功是摩擦力做的功，不是重力做的功"，强调WG=0。
  3. 继续点击「下一步」，依次展开总功、功率、效率的推导，每步右侧公式与左侧高亮联动。
  4. 到达步骤5，对比四个选项，确认A错误、B/C/D正确。
  5. 可随时「上一步」回退复习关键推导环节。

[技术实现]
- JS库选择：原生 SVG + 原生 JavaScript。理由：本场景以静态几何图形、文本标签和显隐/高亮状态切换为主，无需复杂动画或数据驱动绘图；原生SVG足以保证清晰度，且避免引入不必要的库体积。
- 画布尺寸：800 × 500 px（固定）。控件栏位于 SVG 内底部 y=440~490 区域，使用 foreignObject 或 SVG text/rect 绘制按钮，不额外撑高容器。
- 布局草图（ASCII）：
  ```
  +--------------------------------------------------------+
  |                    标题栏 (y=0~50)                      |
  +------------------------+-------------------------------+
  |                        |                               |
  |   装置图区 (x20~400)    |   公式推导区 (x420~780)        |
  |                        |                               |
  |   [物体A]----[滑轮组]-|   W有 = fS  (红)               |
  |      ↑G      |   墙   |   W总 = 3FS (蓝)               |
  |   ←f       F→|       |   P = 3Fυ   (蓝)               |
  |      S               |   η = f/3F  (绿)               |
  |                        |   [A][B]                      |
  |                        |   [C][D]                      |
  +------------------------+-------------------------------+
  |        [◀上一步]  步骤X/5  [下一步▶]  [重置]            |  y=450~490
  +--------------------------------------------------------+
  ```
- 关键实现要点：
  1. 状态机设计：使用变量 `let currentStep = 0;` 控制0~5共6个状态。每个步骤用一个配置对象数组 `stepsConfig` 描述，记录每步应显示/隐藏的元素ID列表、应改变的颜色/透明度属性。
  2. 元素显隐：所有可能动态变化的元素（公式、高亮箭头、选项卡片等）初始 `visibility: hidden` 或 `opacity: 0`，根据 `currentStep` 统一更新。使用 `setAttribute` 修改 SVG 属性，避免 CSS 类冲突。
  3. 颜色/高亮切换：通过修改 `stroke`、`fill`、`opacity` 属性实现。例如步骤1将G箭头stroke从#000改为#aaaaaa，将f箭头stroke改为#c62828。
  4. 约分线：在步骤4时，将预置的灰色虚线 `line` 元素从 `opacity: 0` 设为 `opacity: 1`，位置固定于公式4第一行S字母上方。
  5. 选项卡片：步骤5将四个 `g` 组（每组包含rect、text、对勾/叉）整体显示。A组使用红色样式，B/C/D组使用绿色样式。
  6. 动画曲线：本场景以即时切换为主，无需缓动动画；若需柔和过渡，可对opacity变化添加CSS transition `transition: opacity 0.3s ease`。
  7. 事件绑定：按钮使用 `onclick` 绑定 `prevStep()`、`nextStep()`、`resetStep()` 函数。
- ID命名规范：所有交互元素ID必须以 `scene2-` 为前缀。例如：
  - `scene2-obj-a`（物体A矩形）
  - `scene2-arrow-f`（f箭头）
  - `scene2-formula-wyou`（W有公式）
  - `scene2-card-a`（选项A卡片组）
  - `scene2-btn-next`（下一步按钮）
  - 以此类推。JS中严格使用 `document.getElementById`，禁止 `querySelectorAll` 配合全局class，防止多场景合并时污染。
- IIFE隔离：所有JavaScript代码包裹在 `(function() { ... })();` 中，变量不污染全局作用域。
