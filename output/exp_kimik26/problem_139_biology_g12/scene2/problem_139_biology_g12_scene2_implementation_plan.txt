[图示主题与整合说明]
- 本图示主题：双杂合子（AaBb）自交遗传图解与 F₂ 代表现型比例分析（10:3:3）
- 整合的步骤/概念：
  ① P 代纯合亲本杂交（AAbb × aaBB）；
  ② F₁ 代基因型 AaBb 与表现型白花（A、B 同时存在时 mRNA 结合，酶 A/酶 B 均不能合成）；
  ③ F₁ 产生四种配子 AB、Ab、aB、ab；
  ④ F₂ 棋盘格 4×4 共 16 种基因组合；
  ⑤ 按表现型归类：A_B_（9）+ aabb（1）= 白花 10 份，A_bb（3）= 紫花 3 份，aaB_（3）= 蓝花 3 份，比例 10:3:3。
- 教学价值：教师可逐步展开，从亲本→子一代→子二代，最后通过色块高亮与比例条带直观呈现"互补抑制"导致的特殊分离比，帮助学生建立基因互作与棋盘格之间的映射关系。

[分步序列]
- 初始状态（步骤 1）：显示 P 代杂交基础条件

  - 教师讲解：纯合紫花 AAbb 与纯合蓝花 aaBB 杂交，各自产生一种配子

- 步骤 2：点击「下一步」→ 出现 F₁ 代与配子
  - 新增：F₁ 框(AaBb/白花) 及标签、⊗ 自交符号、F₁ 产生的四种配子 AB/Ab/aB/ab
  - 高亮：AaBb 文字使用 #1565c0 边框或文字色强调；配子标注使用 #c62828 强调
  - 教师讲解：F₁ 为 AaBb，表现型白花（A、B 同时存在，mRNA 结合导致酶无法合成）；F₁ 产生四种数量相等的配子

- 步骤 3：点击「下一步」→ 展开 F₂ 棋盘格
  - 新增：F₂ 标签、4×4 棋盘格（16 个白色背景格子）、8 个配子表头、16 个基因型文字
  - 教师讲解：F₁ 自交，雌雄各四种配子随机结合，形成 16 种基因组合

- 步骤 4：点击「下一步」→ 高亮归类表现型
  - 变化：在 16 个格子上方覆盖半透明色层
    - 白花（灰）：AABB、AABb、AaBB、AaBb(1,4)、AABb(2,1)、AaBb(2,3)、AaBB(3,1)、AaBb(3,2)、AaBb(4,1)、aabb —— 共 10 格

    - 蓝花（青）：aaBB、aaBb(3,4)、aaBb(4,3) —— 共 3 格
  - 教师讲解：按基因型归类表现型，A_B_ 与 aabb 均为白花，A_bb 为紫花，aaB_ 为蓝花

- 步骤 5：点击「下一步」→ 展示表现型比例汇总

[技术实现]
- JS 库选择：原生 SVG（无需外部库）。理由：本场景仅涉及矩形、文本、直线等基础几何元素，原生 SVG 即可满足，减少依赖并保证加载速度。
- 画布尺寸：800 × 500 px（固定）
- 布局草图（ASCII）：
  ```
  800×500 画布
  +----------------------------------------------------------+
  | P  [AAbb]×[aaBB]        F₂   AB    Ab    aB    ab       |
  |     紫花  蓝花          AB  [AABB][AABb][AaBB][AaBb]    |
  |     Ab    aB            Ab  [AABb][AAbb][AaBb][Aabb]    |
  |      \  /               aB  [AaBB][AaBb][aaBB][aaBb]    |
  |       \/                ab  [AaBb][Aabb][aaBb][aabb]    |
  |     [AaBb]⊗                                             |
  |      白花                                               |
  | 配子 AB Ab aB ab                                        |
  |                                                         |
  | F₂表现型比例 [  白花 10/16  ][紫花3/16][蓝花3/16]        |
  |                                                         |
  |           [◀上一步]  步骤 1/5  [下一步▶]                |
  +----------------------------------------------------------+
  ```
- 关键实现要点：
  1. 状态机设计：使用变量 `currentStep`（1~5），每一步对应一个 SVG `<g>` 分组（`scene2-step1-group` 至 `scene2-step5-group`）。通过控制各组的 `display` 属性实现切换。
  2. 步骤 4 的高亮实现：在棋盘格 16 个格子位置预置 16 个 `<rect>` 覆盖层（`scene2-highlight-*`），默认 `display:none`；进入步骤 4 时按表现型类别显示对应覆盖层并赋予不同填充色（灰/紫/青）。
  3. 坐标计算：棋盘格采用固定网格系统，起始 (320,80)，格宽 75，格高 50，间距 10；通过行列索引即可算出每个格子坐标，避免硬编码错误。
  4. 动画曲线：状态切换不使用复杂动画，直接显示/隐藏；如需柔和过渡，可对覆盖层使用 200ms CSS `opacity` 过渡。
  5. 事件绑定：上一步/下一步按钮绑定 `click` 事件，更新 `currentStep` 后调用 `updateScene()` 刷新视图。
  6. 控件栏布局：使用 SVG `<foreignObject>` 在 y=440~490 区域嵌入 HTML `<div>`，采用 `display:flex` 居中排列按钮与文本，不撑高外部容器。
- **ID 命名规范**：所有 SVG 元素及交互控件 ID 必须以 `scene2-` 为前缀，例如 `scene2-p-box-left`、`scene2-step3-group`、`scene2-next-btn`、`scene2-highlight-aabb`。JS 中严格使用 `document.getElementById` 获取元素，禁止跨场景选择器。
- IIFE 隔离：所有 JavaScript 代码包裹在 `(function() { ... })()` 中，避免全局变量污染，确保多场景合并时互不干扰。
