[图示主题与整合说明]
- 本图示主题：带电粒子在矩形磁场边界区域内的圆周运动轨迹与几何约束分析（物理G12第2问）
- 整合的步骤/概念：入射条件→左手定则受力方向→圆心定位→轨迹绘制→圆心到边界垂线几何关系→边界射出条件讨论（左边界/下边界/临界）→联立牛顿第二定律求解磁感应强度B
- 教学价值：教师通过分步导航，按严格逻辑链逐层展开磁场中圆周运动的几何分析法；每步聚焦单一认知点（受力方向判定、圆心定位技巧、垂线距离与边界比较），避免信息过载；边界讨论步骤通过虚实轨迹对比，帮助学生建立"几何约束决定物理结果"的核心思维。

[分步序列]
- 步骤0（入射状态）：显示平行极板、电源连线、磁场矩形（含点阵）、顶点M/N/P/Q、边界名称MN/MP/PQ、宽度d标注、入射速度v箭头、入射角30°弧线。推导面板显示："正离子以速度v从M点射入磁场，与水平方向成30°角。磁场方向垂直纸面向外，区域宽度为d。"
- 步骤1（圆心定位）：新增洛伦兹力F箭头（红色，从M指向左下）、圆心O红色圆点(140,224)、MO灰色虚线、R标签、MO与竖直方向30°角弧（M点左上方）。推导面板显示："左手定则：正电荷，v向右下，B垂直向外，洛伦兹力F垂直v指向左下方。圆心O位于M点沿F方向距离R处。"
- 步骤2（轨迹绘制）：新增圆弧轨迹（绿色粗线），从M点(θ=-60°)顺时针绘制到θ≈30°（约(244,284)），展示运动趋势，不触及边界。推导面板显示："洛伦兹力提供向心力，离子做匀速圆周运动。qvB = mv²/R，半径 R = mv/(qB)。"
- 步骤3（几何分析）：新增三条辅助垂线（O到MN、MP、PQ的灰色虚线）及距离标注（R√3/2在左侧、R/2在下方、d-R√3/2在左侧）。推导面板显示几何关系式：
  "几何关系：
   O到MN距离 = R·cos30° = R√3/2
   O到MP距离 = R·sin30° = R/2
   O到PQ距离 = d − R√3/2"
- 步骤4（边界讨论）：轨迹延伸至实际射出点S(212,320)（情况B，因R√3≈207.8>d=200），显示红色射出点S及标签；以虚线延伸轨迹到左边界(200,327.9)示意情况A；P点(200,320)黄色高亮表示临界参考。推导面板显示：
  "边界讨论：
   若 R√3 < d：从左边界MP射出
   若 R√3 > d：从下边界PQ射出（本例）
   若 R√3 = d：轨迹恰好过P点（临界）"
- 步骤5（公式求解）：保持图形区步骤4状态，推导面板高亮显示核心方程与求解链：
  "qvB = mv²/R  →  R = mv/(qB)
   代入几何边界条件（本例：R√3 > d）
   联立求解磁感应强度B。"

[交互方案]
- 交互类型：分步按钮导航（◀上一步 / 步骤指示器 / 下一步▶ / 重置）
- 控件说明：
  1. 「上一步」按钮：位于(250,452)，宽90px。点击回退到上一步骤，隐藏当前步新增元素，恢复前一步状态。
  2. 「步骤指示器」：位于(355,452)，宽90px，显示"步骤 X/6"，不可点击，仅状态显示。
  3. 「下一步」按钮：位于(460,452)，宽90px。点击前进到下一步，以淡入方式（opacity 0→1，300ms）展示新元素。
  4. 「重置」按钮：位于(565,452)，宽70px。点击立即回到步骤0，所有步骤专属元素隐藏。
- 教师操作流程：
  1. 教师加载图示，默认步骤0，讲解粒子从极板间以30°角进入磁场的初始条件。
  2. 点击「下一步」进入步骤1，配合左手定则讲解受力方向，强调圆心一定在速度垂线上。
  3. 点击「下一步」进入步骤2，展示圆周运动轨迹，建立"洛伦兹力提供向心力"的模型。
  4. 点击「下一步」进入步骤3，引导学生从圆心向各边界作垂线，写出距离表达式——这是本题的解题关键。
  5. 点击「下一步」进入步骤4，讨论边界条件，通过虚实轨迹对比让学生直观理解"为什么有的题从左边界射出，有的从下边界射出"。
  6. 点击「下一步」进入步骤5，联立公式求解B，完成推导闭环。
  7. 可随时点击「上一步」回退复习，或「重置」重新讲解。

[技术实现]
- JS库选择：原生SVG + 原生JavaScript。理由：本场景为纯几何图示（矩形、圆、弧线、箭头、虚线），无复杂数据绑定或3D，原生SVG足以精确控制每个元素的坐标、虚线样式和显隐；无需引入D3/Three.js等重型库，减少加载开销。
- 画布尺寸：800×500 px（固定），SVG设置viewBox="0 0 800 500"。
- 布局草图（ASCII）：
  ```
  +--------------------------------------------------------+
  |  + -  上极板                                           |
  |  | |  下极板                                            |
  |  | |    |                                               |
  |  M+-----+------------------------------------------N   |
  |  | · · · · · · · · · · · · · · · · · · · · · · · · |   |
  |  | · · · · · · · · · · · · · · · · · · · · · · · · | d |
  |  | · · · · · · · · · · · · · · · · · · · · · · · · |   |
  |  | · · · · · · · · · · · · · · · · · · · · · · · · |   |
  |  P-----------------------------------------------Q   |
  |                                                        |
  |  [左侧主图区：0≤x≤480]      [右侧推导区：480<x≤780]    |
  |                                                        |
  |  [◀上一步] [步骤 X/6] [下一步▶] [重置]                  |  y=440~490
  +--------------------------------------------------------+
  ```
- 关键实现要点：
  1. 状态机设计：使用变量`let currentStep = 0;`，定义`const totalSteps = 6;`。每步对应一个要显示的元素ID数组（`stepElements[step]`），切换时遍历所有step-specific元素统一设置`display = 'none'`或`opacity = 0`，再激活当前步元素。
  2. 轨迹path动态计算：步骤2与步骤4共用同一`<path id="scene2-arc-traj">`，通过JS计算SVG path的`d`属性。圆心(140,224)，R=120。步骤2终点角度30°（约(244,284)），步骤4终点角度约53.13°（射出点(212,320)）。使用`A`命令绘制圆弧：`M 200 120 A 120 120 0 0 1 x y`（sweep-flag=1表示顺时针）。
  3. 延伸虚轨迹（情况A示意）：步骤4单独显示`<path id="scene2-arc-ext">`，从实际射出点S继续画到左边界交点(200,327.9)，使用`stroke-dasharray="4,4"`与`opacity="0.4"`区分。
  4. 推导面板：使用绝对定位的HTML `<div id="scene2-formula-panel">`覆盖于SVG上方（`position:absolute; right:20px; top:50px; width:280px;`），内部每步替换innerHTML。避免SVG内<text>换行麻烦，同时满足"图示区仅含视觉元素和短标签"的要求（推导区视为独立面板）。
  5. 淡入动画：对新增元素统一添加CSS类`.scene2-fade-in { animation: fadeIn 0.3s ease-in; }`，通过`@keyframes fadeIn { from { opacity: 0; } to { opacity: 1; } }`实现。
  6. 事件绑定：按钮通过`document.getElementById`获取，绑定`click`事件。上一步/下一步直接修改`currentStep`后调用`renderStep()`；重置直接设`currentStep = 0`并调用`renderStep()`。
  7. 箭头标记：在SVG `<defs>`中定义`<marker id="scene2-arrowhead-black">`与`<marker id="scene2-arrowhead-red">`，分别用于速度和力箭头。
- ID命名规范：所有交互元素ID必须以`scene2-`为前缀，例如`scene2-arc-traj`、`scene2-btn-prev`、`scene2-formula-panel`。JS中严格使用`document.getElementById`获取，禁止全局class选择，避免多场景合并时跨场景污染。
- IIFE隔离：所有JavaScript代码包裹在`(function() { ... })();`中，变量不泄露全局作用域。
