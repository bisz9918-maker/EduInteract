[图示主题与整合说明]
- 本图示主题：密码子碱基替换与基因突变类型（同义突变、错义突变、无义突变）
- 整合的步骤/概念：
  1. 以一段原始mRNA序列（5'-AUG GCU UCA GAA UGG-3'）为基准，展示其编码的氨基酸序列（Met-Ala-Ser-Glu-Trp）。
  2. 同义突变：密码子UCA→UCU，氨基酸仍为Ser，说明密码子简并性。
  3. 错义突变：密码子GAA→GUA，氨基酸由Glu变为Val，联系第(4)问中"甲状腺激素受体功能下降"的分子机制。
  4. 无义突变：密码子UCA→UGA，产生终止密码子，肽链截短，蛋白质功能丧失。
- 教学价值：教师可通过底部四个状态切换按钮，在课堂上逐一对照讲解三种突变类型的差异，帮助学生理解"一个碱基替换"可能导致的不同后果，并与第(4)问的功能下降建立联系。

[分步序列]
本图示采用多状态切换（4个状态），教师通过底部按钮直接跳转对比：

- 状态0（原始序列 / 基准对照）：
  - 显示完整mRNA序列：5'-AUG GCU UCA GAA UGG-3'
  - 所有碱基为黑色，所有密码子框为淡蓝填充(#1565c0, 10%透明度)
  - 氨基酸标签：Met(黑)、Ala(黑)、Ser(黑)、Glu(黑)、Trp(黑)
  - 突变箭头和突变类型标签隐藏
  - 功能说明文字："原始mRNA序列及其编码的氨基酸序列，作为突变分析的基准对照。"
  - 「原始序列」按钮为激活态（蓝底白字），其余按钮为未激活态

- 状态1（同义突变）：
  - 碱基变化：密码子3第3位 A→U（位置445,150），该碱基显示为红色U，加粗
  - 密码子3框填充变为淡红(#c62828, 10%透明度)
  - 氨基酸Ser仍为黑色（未改变）
  - 显示突变箭头：从(415,90)垂直向下指向(415,120)，绿色#2e7d32
  - 显示突变类型标签："同义突变"在(415,80)，绿色#2e7d32
  - 功能说明文字："密码子 UCA → UCU，编码氨基酸仍为 Ser（丝氨酸）。由于密码子的简并性，碱基替换未改变氨基酸序列，蛋白质功能通常不变。"
  - 「同义突变」按钮为激活态（绿底白字）

- 状态2（错义突变）：
  - 碱基变化：密码子4第2位 A→U（位置525,150），该碱基显示为红色U，加粗
  - 密码子4框填充变为淡红(#c62828, 10%透明度)
  - 氨基酸变化：密码子4下方由Glu变为Val，Val显示为红色#c62828
  - 显示突变箭头：从(525,90)垂直向下指向(525,120)，红色#c62828
  - 显示突变类型标签："错义突变"在(525,80)，红色#c62828
  - 功能说明文字："密码子 GAA → GUA，编码氨基酸由 Glu（谷氨酸）变为 Val（缬氨酸）。氨基酸改变可能导致蛋白质空间结构变化，功能下降（如本题甲状腺激素受体功能下降）。"
  - 「错义突变」按钮为激活态（红底白字）

- 状态3（无义突变）：
  - 碱基变化：密码子3第2位 C→G（位置415,150），该碱基显示为红色G，加粗
  - 密码子3框填充变为淡红(#c62828, 10%透明度)
  - 氨基酸变化：密码子3下方由Ser变为"STOP"，红色#c62828 加粗
  - 密码子4、5的氨基酸标签(Glu、Trp)变为灰色#888888，透明度0.4，表示翻译终止后不再合成
  - 显示突变箭头：从(415,90)垂直向下指向(415,120)，红色#c62828
  - 显示突变类型标签："无义突变"在(415,80)，红色#c62828
  - 功能说明文字："密码子 UCA → UGA（终止密码子），翻译在此提前终止，肽链截短。产生的蛋白质通常完全丧失功能。"
  - 「无义突变」按钮为激活态（红底白字）

  4. 强调状态3（无义突变）导致肽链截短，与状态2的"功能下降"形成程度对比。

[技术实现]
- JS库选择：原生SVG + 原生JavaScript。原因：本场景为静态图形的状态切换，无复杂动画、无数据驱动绘图、无3D需求，原生SVG足以高效实现，且便于精确控制每个碱基、每个框的样式属性。
- 画布尺寸：800 × 500 px（SVG viewBox="0 0 800 500"）
- 布局草图（ASCII）：
  ```
  +--------------------------------------------------------+
  |                    标题区 (y=0~60)                      |
  |              "密码子碱基替换与基因突变类型"               |
  +--------------------------------------------------------+
  |                    主图区 (y=60~300)                    |
  |    5' ----AUG---GCU---UCA---GAA---UGG---- 3'           |
  |         [Met] [Ala] [Ser] [Glu] [Trp]                  |
  |            ↑突变标注（状态切换时显示）                    |
  +--------------------------------------------------------+
  |                  说明区 (y=300~430)                     |
  |         [功能影响说明文字框，随状态变化]                   |
  +--------------------------------------------------------+
  |                  控件区 (y=430~500)                     |
  |   [原始序列] [同义突变] [错义突变] [无义突变]            |
  +--------------------------------------------------------+
  ```
- 关键实现要点：
  1. 状态机设计：定义常量 STATE = { ORIGINAL: 0, SYNONYMOUS: 1, MISSENSE: 2, NONSENSE: 3 }。当前状态变量 currentState，初始值为0。
  2. 渲染函数 renderState(state)：根据state值，批量设置以下元素的属性：
     - 碱基文字内容/颜色/字体粗细（通过 setAttribute 或 style）
     - 密码子框填充色（通过 setAttribute('fill', ...) 和 setAttribute('fill-opacity', ...)）
     - 氨基酸文字内容/颜色/透明度
     - 突变箭头/标签的 display 属性（'block'/'none'）及位置
     - 功能说明文字内容
     - 按钮激活态样式（通过切换class：active-original / active-synonymous / active-missense / active-nonsense）
  3. 坐标计算：所有坐标硬编码在初始化函数中，不依赖动态计算，确保代码agent可直接复制坐标值。
  4. 动画曲线：状态切换无需动画，直接瞬时切换，保证课堂讲解的响应速度。若需柔和过渡，可给相关元素添加 CSS transition: all 0.2s ease。
  5. 事件绑定：每个按钮绑定 onclick 事件，调用 setState(newState) → renderState(currentState)。
  6. 密码子框与碱基对齐：密码子框宽90px，内部3个碱基等距分布，x偏移分别为-30, 0, +30（相对框中心），确保视觉均匀。
  7. 终止密码子表达：状态3中，密码子3下方氨基酸改为"STOP"，密码子4、5的氨基酸标签设置 opacity=0.3 和 fill=#888888，直观表达翻译提前终止。
- ID命名规范（所有元素必须以 scene3- 为前缀）：
  - scene3-title
  - scene3-mrna-line
  - scene3-label-5prime / scene3-label-3prime
  - scene3-codon-1-box ~ scene3-codon-5-box
  - scene3-codon-1-num ~ scene3-codon-5-num
  - scene3-base-1-1 ~ scene3-base-5-3（第一位为密码子序号，第二位为密码子内碱基序号）
  - scene3-aa-1 ~ scene3-aa-5
  - scene3-mutation-arrow / scene3-mutation-label
  - scene3-desc-box / scene3-desc-text
  - scene3-btn-original / scene3-btn-synonymous / scene3-btn-missense / scene3-btn-nonsense
- IIFE隔离：所有JavaScript代码包裹在 (function() { ... })() 中，避免全局变量污染，确保多场景合并时互不干扰。
