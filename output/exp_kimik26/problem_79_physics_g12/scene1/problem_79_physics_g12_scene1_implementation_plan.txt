[图示主题与整合说明]
- 本图示主题：滑块-木板模型情景与隔离受力分析（含第一问临界条件）
- 整合的步骤/概念：
  1. 题目初始情景（光滑水平面、木板 M、位于最右端的物块 m，标注 L）；
  2. 物块 m 的隔离受力分析（重力 mg、支持力 N₁、滑动摩擦力 f、加速度 a_m）；
  3. 木板 M 的隔离受力分析（重力 Mg、地面支持力 N₂、物块压力 N₁′、摩擦力 f′、拉力 F、加速度 a_M）；
  4. 第一问临界加速度与临界拉力推导（a_m = μg = 1 m/s²，a_M = (F−μmg)/M，抽出条件 a_M > a_m，得 F > 4 N）。
- 教学价值：教师通过「情景→隔离→临界」三步递进，引导学生理解"抽出"的动力学本质是两物体加速度不同；分步按钮便于教师控制课堂节奏，随时回退复习。

[分步序列]
- 步骤 0（初始状态）：
  - 左栏显示完整情景：地面、木板 M、物块 m（在最右端）、拉力 F 箭头、长度 L 标注、已知条件参数框。
  - 右栏空白，仅显示淡灰色提示文字 "点击「下一步」开始受力分析"（居中，#888888）。
  - 上一步按钮禁用（灰色）。

- 步骤 1（物块 m 隔离受力）：
  - 左栏：物块 m 高亮（fill-opacity=0.30，stroke-width=3），其余元素保持常态。
  - 右栏：显示物块 m 受力分析组——标题"物块 m 受力分析"（红色）、物块矩形、重力 mg（向下）、支持力 N₁（向上）、摩擦力 f（向右，标注 f=μmg）、虚线加速度 a_m（向右）。
  - 逻辑说明：摩擦力 f 是木板对物块向右的静/滑动摩擦力，是物块产生加速度的原因。

- 步骤 2（木板 M 隔离受力）：
  - 左栏：木板 M 高亮（fill-opacity=0.30，stroke-width=3），物块 m 恢复常态。
  - 右栏：隐藏 m 受力组，显示木板 M 受力分析组——标题"木板 M 受力分析"（蓝色）、木板矩形（比 m 矩形大以体现质量差异）、重力 Mg（向下）、地面支持力 N₂（向上）、物块压力 N₁′（向上）、摩擦力 f′（向左）、拉力 F（向右，绿色）、虚线加速度 a_M（向右）。
  - 逻辑说明：f′ 与 f 是一对作用力与反作用力，大小相等方向相反。

- 步骤 3（临界条件推导）：
  - 左栏：拉力 F 箭头高亮（stroke-width=3，绿色），其余恢复常态。
  - 右栏：隐藏受力图，显示推导公式组——标题"临界条件推导"、分隔线、对 m 的方程 f=μmg=ma_m 得 a_m=μg=1m/s²（红色）、对 M 的方程 F−f′=Ma_M 得 a_M=(F−μmg)/M、抽出条件 a_M>a_m、临界值 F₀=μ(M+m)g=4N、最终结论 "F > 4 N"（绿色，22px加粗）。
  - 逻辑说明：只有木板加速度大于物块加速度，两者才会分离；临界拉力为 4N。

- 教师可随时点击「上一步」回退到任意步骤复习。

[交互方案]
- 交互类型：分步按钮导航（◀ 上一步 / 下一步 ▶）。
- 控件说明：
  - 「上一步」按钮：位于 (250,455)，100×35px；点击回退到上一状态；在步骤 0 时禁用（灰色）。

- 教师操作流程：
  1. 教师展示步骤 0，说明题目情景与已知条件；
  2. 点击「下一步」进入步骤 1，讲解物块 m 的受力，强调摩擦力方向向右；
  3. 点击「下一步」进入步骤 2，讲解木板 M 的受力，强调 f 与 f′ 的相互作用关系；
  4. 点击「下一步」进入步骤 3，展示公式推导，强调临界条件 a_M > a_m，得出 F > 4N；
  5. 可随时点击「上一步」回退，针对学生疑问重复讲解某一步。

[技术实现]
- JS 库选择：原生 SVG + 原生 JavaScript。理由：本场景以几何图形、箭头、文本为主，无复杂函数图或 3D，原生 SVG 性能最佳且无需额外 CDN。
- 画布尺寸：800 × 500 px（SVG 容器）。
- 布局草图：
  ```
  [图示区 800×500]
  +--------------------------------------------------+
  | 左栏：情景图              |  右栏：受力/推导      |
  |  ┌──────────────┐        |  ┌────────────────┐  |
  |  │  木板 M       │        │  标题/公式/受力图 │  |
  |  │    ┌──┐      │        │                  │  |
  |  │    │m │  F→  │        │                  │  |
  |  └────┴──┴──────┘        │                  │  |
  |  参数框(左上)             │                  │  |
  |                          |                  │  |
  +--------------------------------------------------+
  |        [◀上一步]  步骤 X/4  [下一步▶]            |  y=450~490
  +--------------------------------------------------+
  ```
- 关键实现要点：
  1. **SVG 结构**：在 `<defs>` 中定义 4 种颜色箭头 marker（black、red、blue、green），以及虚线加速度箭头 marker；所有视觉元素按步骤分 `<g>` 组（如 `scene1-step0-group`、`scene1-step1-group` 等），通过设置 `display: none/block` 切换。
  2. **状态机设计**：变量 `currentStep`（0~3），`totalSteps = 4`。`updateScene()` 函数根据 currentStep 控制：
     - 各步骤组的显示/隐藏；
     - 左栏高亮元素（通过修改对应元素的 `fill-opacity` 和 `stroke-width` 属性）；
     - 按钮禁用状态（修改 `disabled` 属性及填充色）；
     - 步骤指示器文本更新。
  3. **坐标计算**：所有坐标硬编码为计划中的精确值；箭头使用 `<line>` + `<marker-end>`；虚线加速度箭头使用 `stroke-dasharray="5,3"`。
  4. **动画曲线**：本场景为静态分步切换，无需 CSS 动画或 JS 插值；若需柔和过渡，可在切换时给 SVG 组添加 150ms 的 opacity 过渡（CSS `transition: opacity 0.15s`）。
  5. **事件绑定**：上一步/下一步按钮绑定 `click` 事件，修改 `currentStep` 后调用 `updateScene()`。
- **ID 命名规范**：所有交互元素 ID 必须以 `scene1-` 为前缀。例如：
  - `scene1-plank`（木板矩形）
  - `scene1-block`（物块矩形）
  - `scene1-step1-group`（步骤1右栏组）
  - `scene1-btn-prev`、`scene1-btn-next`（按钮）
  - `scene1-step-indicator`（步骤指示器）
  JS 中统一使用 `document.getElementById` 获取元素，禁止全局 class 选择，避免多场景合并时跨场景污染。
- **IIFE 隔离**：所有 JavaScript 代码包裹在 `(function() { ... })();` 中，内部变量不污染全局作用域。
