[图示主题与整合说明]
- 本图示主题：中点P的轨迹探索（问题第3问）
- 整合的步骤/概念：
  1. 固定基线AB=8，标注定点M、N（AM=BN=2）
  2. 动点C在MN区间运动，实时构造等边△ACD（蓝）与△BCE（绿）
  3. 实时连接DE，标出中点P
  4. 通过滑块控制C的连续运动，观察P的轨迹
  5. 轨迹拖尾直观展示P的路径为水平线段，揭示y_P恒为2√3
  6. 标注轨迹端点P₁、P₂及路径长度=2
- 教学价值：教师通过拖动滑块让学生自主发现"动中求静"的规律——尽管C在动、三角形在变形，但P的纵坐标保持不变，轨迹为水平线段。轨迹开关和拖尾帮助学生从直观感知过渡到定量验证。

[分步序列]
本场景为连续拖拽/滑块交互，非分步导航。以下描述状态变化与教师讲解节奏：

- 初始状态（步骤0）：
  - C位于M点（x=2，画布坐标(300,420)）
  - 显示完整几何构造：AB、M、N、△ACD（蓝）、△BCE（绿）、DE、P点
  - P位于(350,247)
  - 参考虚线y=247可见
  - 轨迹固定线与拖尾均隐藏
  - 坐标标注显示"P(3, 2√3)"
  - 教师可讲解初始构型

- 状态1（拖动滑块，C从M向N运动）：
  - 教师拖动底部滑块，C在(300,420)到(500,420)之间连续移动
  - △ACD与△BCE实时变形：D从(250,333)移至(350,160)，E从(450,160)移至(550,333)
  - DE实时更新，P点在y=247水平线上从(350,247)移至(450,247)
  - 坐标标注实时更新，如"P(4.0, 2√3)"
  - 教师引导学生观察：P只在水平移动，高度不变

- 状态2（开启轨迹显示）：
  - 点击"显示轨迹"按钮
  - 固定轨迹线段P₁P₂（红色粗线）显现
  - 端点P₁、P₂标记及"路径长 = 2"标注出现
  - 再次拖动C，P点运动留下红色拖尾（polyline），拖尾与固定轨迹线重合，验证轨迹为直线段
  - 教师强调：无论C如何运动，P始终落在同一条水平线上

- 状态3（清除与重试）：
  - 点击"清除轨迹"按钮，拖尾清空
  教师可让学生再次拖动，自主验证规律

- 最终揭示：
  - 轨迹完整展示，配合坐标标注y=2√3恒定
  - 路径长度=2醒目标注
  - 教师总结：P的轨迹是平行于AB的水平线段，长度为MN长度的一半（2单位）

逐对检查关键潜在冲突：
1. "A"(200,445) 与 "AM=2"(250,435)：间距√(50²+10²)≈51px → 无冲突
2. "B"(600,445) 与 "BN=2"(550,435)：间距√(50²+10²)≈51px → 无冲突
3. "M"(300,455) 与 "C"(300,410)：当C在M时，间距45px → 无冲突
4. "N"(500,455) 与 "C"(500,410)：当C在N时，间距45px → 无冲突
5. "AB=8"(400,445) 与 "A"/"B"：间距200px → 无冲突
6. "P"(362~462, 235) 与 "路径长 = 2"(400,270)：最小间距（P在362时）√(38²+35²)≈52px → 无冲突
7. "P₁"(300,267) 与 "路径长 = 2"(400,270)：间距100px → 无冲突
8. "P₂"(500,267) 与 "路径长 = 2"(400,270)：间距100px → 无冲突
9. "坐标标注"(370~470, 222) 与 "P"(362~462, 235)：间距约13~17px，略近。解决方案：坐标标注改为(P.x+25, P.y-30)，即(375~475, 217)，与P标签间距√(13²+18²)≈22px，满足≥20px
10. "D"(238~338, 148~321) 与 "E"(458~558, 148~321)：水平间距始终≥120px → 无冲突
11. "D"/"E" 与 三角形边：标签在顶点外侧偏移，不压边

所有标签间距满足≥20px要求，无重叠风险。

[交互方案]
- 交互类型：连续拖拽/滑块 + 按钮开关
- 控件说明：
  1. 滑块（底部中央，x=250~550, y=460~480区域）：
     - 轨道长300px，对应C在MN间运动（AC从2到6）
     - 滑块按钮红色，半径10px，随值水平移动
     - 拖动时实时更新整个几何图形
  2. "显示轨迹"按钮（底部左侧，(80,455)-(170,485)）：
     - 点击后：显示固定轨迹线段P₁P₂、端点标记P₁/P₂、"路径长=2"标注
     - 同时启用拖尾记录，P运动时留下红色轨迹
     - 按钮文字变为"隐藏轨迹"，再次点击可隐藏固定线（拖尾保留至清除）
  3. "清除轨迹"按钮（底部右侧，(630,455)-(720,485)）：
     - 点击后清空拖尾polyline的点数组，移除所有历史轨迹
     - 不影响固定轨迹线（若已显示则保留）
- 教师操作流程：
  1. 展示初始状态，确认C在M点时的几何关系
  2. 缓慢拖动滑块，让学生观察P的水平移动
  3. 点击"显示轨迹"，再次拖动，让学生看到拖尾形成直线
  4. 引导学生注意坐标标注中y值始终为2√3
  5. 指出P₁、P₂位置，验证路径长度=2
  6. 点击"清除轨迹"，让学生亲自拖动验证

[技术实现]
- JS库选择：原生SVG + 原生JavaScript。理由：本场景以2D几何图形和简单动画为主，无需复杂图表或3D。原生SVG可直接操作DOM属性，配合requestAnimationFrame实现流畅拖拽更新，避免引入不必要库。
- 画布尺寸：800 × 500 px（固定）
- 布局草图：
  ```
  [画布 800×500]
  
  y=0    ┌────────────────────────────────────────┐
         │      D(蓝)        E(绿)               │
         │       /\          /\                  │
         │      /  \        /  \                 │
         │     /    \      /    \                │
         │    / △ACD\    / △BCE \               │
  y=160  │   /        \  /        \              │
         │  /          \/          \             │
  y=247 ─┼─P₁──────────P──────────P₂── 轨迹红线 │ ← 参考虚线
         │            /|\                      │
         │           / | \                     │
         │          /  |  \   DE               │
  y=420  │    A────M───C───N────B              │
         │    └─2─┘       └─2─┘                │
  y=440  │  [显示轨迹] [====滑块====] [清除轨迹] │
  y=500  └────────────────────────────────────────┘
         x=0                                    x=800
  
  主图区：y=50~430（上方留50px给D/E顶点，下方留70px给控件）
  控件区：y=440~490（SVG内绝对定位div覆盖）
  ```
- 关键实现要点：
  1. 坐标映射：几何单位→画布像素，比例尺50px/单位。A为原点(200,420)。公式：
     - C = (200 + 50*x, 420)
     - D = (200 + 25*x, 420 - 25*x*Math.sqrt(3))
     - E = (400 + 25*x, 420 - (200 - 25*x)*Math.sqrt(3))
     - P = (300 + 25*x, 420 - 100*Math.sqrt(3))  // y恒定≈247
     其中x∈[2,6]
  2. 状态机设计：
     - state = { x: 2, showTrack: false, trailPoints: [] }
     - 滑块input事件 → 更新state.x → 调用render()
     - render()重新计算D、E、P坐标，更新所有SVG元素的d/cx/cy/x1/y1/x2/y2属性
     - 若showTrack为true，将当前P坐标push到trailPoints，更新拖尾polyline的points属性
  3. 动画曲线：无需缓动，滑块直接映射坐标，保证几何约束的实时性和准确性
  4. 事件绑定：
     - 滑块input事件监听
     - 按钮click事件监听
     - 所有DOM更新在requestAnimationFrame中批量执行，避免频繁重绘
  5. 轨迹拖尾优化：限制trailPoints最大长度（如500点），防止内存泄漏。由于轨迹是直线，实际上点数不会过多。
  6. 固定轨迹线：直接用line元素从(300,247)到(500,247)，通过display/visibility控制显隐，无需动态计算。
  7. 坐标标注：使用text元素，内容模板`P(${(x+4)/2}, 2√3)`，数值保留1位小数。

  - P₁点：scene2-point-p1
  - P₂点：scene2-point-p2
