[图示主题与整合说明]
- 本图示主题：恒容（甲）与恒压（乙）对化学平衡影响的对比
- 整合的内容：对比甲和乙容器在 2NO₂ ⇌ N₂O₄ 反应中，恒容与恒压条件下平衡位置的差异
- 教学价值：教师可通过拖拽滑块调节反应进度，直观展示恒容容器中压强变化导致平衡移动，而恒压容器中体积变化导致平衡移动，帮助学生理解勒夏特列原理在不同约束条件下的表现

[分步序列]
本场景采用连续拖拽交互，无分步导航，状态随滑块位置连续变化：

- 初始状态（进度 0%）：
  - 甲容器：显示 20 个蓝色 NO₂ 分子，0 个绿色 N₂O₄ 分子
  - 乙容器：显示 20 个蓝色 NO₂ 分子，0 个绿色 N₂O₄ 分子，活塞在顶部 (y=100)
  - 滑块按钮在最左侧 (x=200)
  - 数据面板显示：甲 N₂O₄%=0.0%，乙 N₂O₄%=0.0%

- 进度 25%：
  - 甲容器：约 5 个 NO₂ 转化为 N₂O₄，显示 15 个 NO₂ + 5 个 N₂O₄
  - 乙容器：约 5 个 NO₂ 转化为 N₂O₄，显示 15 个 NO₂ + 5 个 N₂O₄，活塞下移至 y=115（体积缩小约 15%）
  - 滑块按钮在 x=300
  - 数据面板显示：甲 N₂O₄%≈25%，乙 N₂O₄%≈28%

- 进度 50%：
  - 甲容器：约 10 个 NO₂ 转化为 N₂O₄，显示 10 个 NO₂ + 10 个 N₂O₄
  - 乙容器：约 10 个 NO₂ 转化为 N₂O₄，显示 10 个 NO₂ + 10 个 N₂O₄，活塞下移至 y=130（体积缩小约 30%）
  - 滑块按钮在 x=400
  - 数据面板显示：甲 N₂O₄%≈40%，乙 N₂O₄%≈45%

- 进度 75%：
  - 甲容器：约 14 个 NO₂ 转化为 N₂O₄，显示 6 个 NO₂ + 14 个 N₂O₄
  - 乙容器：约 14 个 NO₂ 转化为 N₂O₄，显示 6 个 NO₂ + 14 个 N₂O₄，活塞下移至 y=145（体积缩小约 45%）
  - 滑块按钮在 x=500
  - 数据面板显示：甲 N₂O₄%≈55%，乙 N₂O₄%≈62%

- 最终状态（进度 100%，平衡态）：
  - 甲容器：约 16 个 NO₂ 转化为 N₂O₄，显示 4 个 NO₂ + 16 个 N₂O₄
  - 乙容器：约 18 个 NO₂ 转化为 N₂O₄，显示 2 个 NO₂ + 18 个 N₂O₄，活塞下移至 y=160（体积缩小约 60%）
  - 滑块按钮在最右侧 (x=600)
  - 数据面板显示：甲 N₂O₄%≈65%，乙 N₂O₄%≈75%
  - 结论标注高亮："乙中 N₂O₄% > 甲中 N₂O₄%"

[交互方案]
- 交互类型：连续拖拽滑块 — 滑块控制反应进度（0%→100%）
- 控件说明：
  1. 滑块轨道：位于 (200,390)-(600,390)，灰色，长度 400px
  2. 滑块按钮：蓝色圆形，可沿轨道拖拽，位置对应反应进度
  3. 进度显示文本：位于滑块下方，实时显示"反应进度：X%"
  4. 数据面板：位于右侧 (680,80)-(780,200)，实时显示甲、乙容器中 N₂O₄ 百分含量
- 教师操作流程：
  1. 初始状态展示：两个容器均只有 NO₂ 分子，N₂O₄ 含量为 0%
  2. 拖拽滑块向右移动，观察分子转化过程
  3. 对比甲、乙容器中分子数量变化：甲容器体积不变，乙容器活塞下移体积缩小
  4. 观察数据面板中 N₂O₄ 百分含量变化：乙始终高于甲
  5. 拖拽至 100% 时，强调结论：恒压条件下平衡更向气体分子数减少的方向移动，故乙中 N₂O₄% > 甲中 N₂O₄%

[技术实现]
- JS 库选择：原生 SVG + 原生 JavaScript（简单几何和交互，无需重型库）
- 画布尺寸：800 × 500 px
- 布局草图（ASCII）：
  ```
  ┌────────────────────────────────────────────────────────────────┐
  │                        2NO₂ ⇌ N₂O₄                             │  y=25
  │                                                                │
  │    ┌──────────────┐              ┌──────────────┐              │
  │    │   甲容器     │              │   乙容器     │              │
  │    │  (恒容)      │              │  (恒压)      │              │
  │    │  [NO₂分子]   │              │  [NO₂分子]   │              │
  │    │  [N₂O₄分子]  │              │  [N₂O₄分子]  │              │
  │    │              │              │  [活塞移动]  │              │
  │    └──────────────┘              └──────────────┘              │  y=100-320
  │         甲                              乙                      │  y=350
  │                                                                │
  │              ┌──────────────────────────┐                      │
  │              │    滑块轨道 (400px)      │                      │  y=390
  │              │    ●─────────────────    │                      │

  │              └──────────────────────────┘                      │
  │                                                                │
  │    数据面板：                                                   │
  │    N₂O₄ 含量对比                                               │  y=80-200
  │    甲：XX.X%                                                   │
  │    乙：XX.X%                                                   │
  │                                                                │
  └────────────────────────────────────────────────────────────────┘
  ```

- 关键实现要点：
  1. 状态机设计：
     - 使用变量 `progress` (0-100) 表示反应进度
     - 根据 progress 计算 NO₂ 和 N₂O₄ 分子数量
     - 甲容器：分子总数不变，仅比例变化
     - 乙容器：分子总数减少，活塞位置根据体积变化调整

  2. 坐标计算：
     - 滑块按钮 x = 200 + progress × 4
     - 乙容器活塞 y = 100 + progress × 0.6（最大下移 60px）
     - 分子随机分布：在容器内随机生成坐标，避免重叠

  3. 分子分布算法：
     - 使用简单碰撞检测避免分子重叠
     - NO₂ 分子半径 8，N₂O₄ 分子半径 10
     - 初始 20 个 NO₂，随进度转化为 N₂O₄

  4. 平衡计算（简化模型）：
     - 甲（恒容）：平衡时 N₂O₄% ≈ 65%
     - 乙（恒压）：平衡时 N₂O₄% ≈ 75%
     - 中间进度使用线性插值或简单曲线模拟

  5. 事件绑定：
     - 滑块拖拽：mousedown + mousemove + mouseup
     - 触摸支持：touchstart + touchmove + touchend
     - 实时更新：拖拽时触发 render() 函数

  6. ID 命名规范：
     - 所有元素 ID 以 `scene3-` 为前缀
     - 示例：scene3-container, scene3-slider, scene3-jia-container, scene3-yi-container, scene3-jia-no2, scene3-yi-no2, scene3-jia-n2o4, scene3-yi-n2o4, scene3-piston, scene3-data-jia, scene3-data-yi

  7. IIFE 隔离：
     - 所有 JS 代码包裹在 (function() { ... })() 中
     - 避免全局变量污染

  8. 渲染优化：
     - 使用 requestAnimationFrame 平滑更新
     - 分子位置预计算，避免每帧重新随机
