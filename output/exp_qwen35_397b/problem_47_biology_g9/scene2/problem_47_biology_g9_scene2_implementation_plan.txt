[图示主题与整合说明]
- 本图示主题：选项 A 验证—肾小管功能异常的影响
- 整合的内容：正常尿液形成过程 vs 肾小管被麻痹后的对比 + 蛋白质在尿液形成中的去向分析
- 教学价值：教师可通过切换两种状态，直观展示肾小管功能与蛋白质过滤的关系。学生能清晰看到：无论肾小管是否麻痹，蛋白质始终在肾小球处被阻挡，不会进入原尿或尿液。从而验证选项 A"若用麻药麻痹正常人的乙处，则 b 中会有蛋白质"是错误的。

[分步序列]
本场景采用多状态切换交互（2 个状态），非分步导航：

- 初始状态（默认显示状态1-正常）：
  - 显示肾小球框、甲框、乙框、箭头1、箭头2
  - 显示蛋白质分子在肾小球内 (150,100)
  - 显示蛋白质阻挡线在肾小球出口 (215,140)-(225,180)
  - 甲、乙框为绿色边框 #2e7d32
  - a 标签在甲上方，b 标签在乙上方
  - 原尿区、尿液区标识为绿色
  - 结论区显示："状态1（正常）：蛋白质被肾小球阻挡，原尿(a)和尿液(b)中均无蛋白质"
  - 状态1按钮高亮，状态2按钮普通

- 状态1（正常）：
  - 与初始状态相同
  - 蛋白质分子停留在肾小球内，无法通过阻挡线
  - 甲、乙区域无蛋白质分子
  - 结论："✓ 正常状态下，蛋白质无法通过肾小球过滤膜，原尿和尿液中均不含蛋白质"

- 状态2（肾小管麻痹）：
  - 乙框变为红色边框 #c62828，填充 #ffcdd2
  - 乙框上方显示"麻痹"标识 (520,80)
  - 箭头2变为红色 #c62828
  - 蛋白质分子仍停留在肾小球内 (150,100)，阻挡线仍显示
  - 甲、乙区域仍无蛋白质分子（关键：蛋白质从未进入原尿）
  - 尿液区标识变为红色
  - 结论区显示："✗ 选项 A 错误：即使肾小管(乙)被麻痹，蛋白质仍在肾小球处被阻挡，b(尿液)中不会有蛋白质"
  - 右侧显示红色×标记 (680,350)
  - 状态2按钮高亮，状态1按钮普通

[交互方案]
- 交互类型：多状态切换（2 个状态按钮）
- 控件说明：
  - 状态1按钮："正常状态" | 位置 (150,30) | 120×35px | 点击切换到正常尿液形成流程
  - 状态2按钮："肾小管麻痹" | 位置 (530,30) | 150×35px | 点击切换到肾小管被麻痹的异常状态
- 教师操作流程：
  1. 默认显示状态1，教师讲解正常尿液形成过程：血液流经肾小球时，大分子蛋白质被过滤膜阻挡，无法进入原尿
  2. 点击"肾小管麻痹"按钮，切换到状态2，教师强调：即使肾小管功能受阻，蛋白质仍然在肾小球处被阻挡，根本不会到达肾小管
  3. 引导学生观察两种状态下蛋白质的位置始终在肾小球内，从而得出选项 A 错误的结论
  4. 可反复切换对比，强化理解

[技术实现]
- JS 库选择：原生 SVG（简单流程图，无需复杂库）
- 画布尺寸：800 × 500 px
- 布局草图（ASCII）：
  ```
  [800×500 画布]
  ┌─────────────────────────────────────────────────────────────┐
  │  [正常状态]                    [肾小管麻痹]                 │ y=20-60
  ├─────────────────────────────────────────────────────────────┤
  │                                                             │
  │   ┌─────────┐    →    ┌───────┐    →    ┌───────┐          │ y=120-200
  │   │ 肾小球  │  蛋白质  │  甲   │         │  乙   │          │
  │   │         │  ●      │       │         │       │          │
  │   └─────────┘         └───────┘         └───────┘          │
  │                        a                   b               │
  │                                                             │
  │                    原尿(a)              尿液(b)             │ y=220
  │                                                             │
  ├─────────────────────────────────────────────────────────────┤
  │  ┌─────────────────────────────────────────────────────┐   │ y=320-400
  │  │  结论说明区（动态文字 + 错误标记）                    │   │
  │  └─────────────────────────────────────────────────────┘   │
  ├─────────────────────────────────────────────────────────────┤
  │  [◀ 上一步]  [下一步 ▶]  （如有分步导航则显示）              │ y=440-490
  └─────────────────────────────────────────────────────────────┘
  ```
- 关键实现要点：
  1. 状态机设计：使用 currentState 变量（1 或 2），点击按钮时更新状态并重绘相关元素
  2. 元素分组：将状态1特有元素、状态2特有元素、共有元素分别用<g>分组，通过 display 属性控制显示/隐藏
  3. 蛋白质分子：始终显示在肾小球内，不随状态变化移动（强调蛋白质从未进入原尿）
  4. 颜色切换：乙框、箭头2、尿液区标识的颜色根据状态动态切换
  5. 结论文字：根据状态动态更新文本内容
  6. 事件绑定：按钮点击事件绑定到切换函数，使用 addEventListener
- ID 命名规范：
  - 所有元素 ID 以 scene2- 为前缀
  - 示例：scene2-renal-corpuscle（肾小球）、scene2-jia（甲）、scene2-yi（乙）、scene2-protein（蛋白质）、scene2-btn-normal（状态1按钮）、scene2-btn-paralyzed（状态2按钮）、scene2-conclusion（结论区）
- IIFE 隔离：所有 JS 代码包在 (function() { ... })() 中，避免全局变量污染
