[分步序列]
本场景为连续交互型，无分步导航，采用滑块控制：
- 初始状态（滑块 0°）：G 在 BC 中点附近，H 在 AD 中点附近，平面α处于基准位置
- 拖动滑块（0°~180°）：G 沿 BC 线段滑动，H 沿 AD 线段联动滑动，四边形 EGFH 形状实时变化
- 滑块极端位置（0°或 180°）：G 接近 B 或 C，H 接近 A 或 D，展示平面α的极限位置

[交互方案]
- 交互类型：连续拖拽滑块
- 控件说明：
  - 滑块轨道：位于 SVG 底部 y=450~480 区域，宽度 300px，水平居中 (x=250~550)
  - 滑块头：可拖拽，指示当前平面α旋转角度
  - 角度显示：滑块下方显示当前角度值（0°~180°）
- 教师操作流程：
  1. 初始状态展示四面体基础结构，E、F 中点位置
  2. 拖动滑块，观察 G、H 如何随平面α旋转而联动变化
  3. 停在特定角度，讲解此时四边形 EGFH 的几何特征
  4. 拖动到极端位置，说明平面α的极限情况

[技术实现]
- JS 库选择：原生 SVG + 原生 JavaScript
  - 原因：几何图形简单，无需复杂库；SVG 便于精确控制坐标和样式；原生 JS 足够处理滑块交互和坐标计算
- 画布尺寸：800 × 500 px
- 布局草图：
  ```
  [图示区 800×440]
     A(400,80)
        /\
       /  \
      /    \
     E      \
    / \      \
   B---G------H---D
    \   \    /   /
     \   \  /   /
      \   F    /
       \  |   /
        \ |  /
         \| /
          C(400,420)
  
  [控件栏 y=440~500]
  [====滑块轨道====] 0°~180°
       角度显示
  ```
- 关键实现要点：
  1. 坐标计算：G 在 BC 上的位置由参数 t∈[0,1] 决定，H 在 AD 上的位置由平面α过 EF 的几何约束决定
  2. 平面约束：E、F、G、H 四点共面，利用向量叉积验证共面条件
  3. 参数化：设 G = B + t*(C-B)，则 H 的位置由共面条件解出
  4. 滑块映射：滑块值 0~100 映射到 t∈[0.1, 0.9]（避免端点退化）
  5. 动画平滑：使用 requestAnimationFrame 实现平滑拖动效果
- ID 命名规范：所有元素 ID 以 scene1- 为前缀
  - scene1-vertex-a, scene1-vertex-b, scene1-vertex-c, scene1-vertex-d
  - scene1-edge-ab, scene1-edge-ac, scene1-edge-ad, scene1-edge-bc, scene1-edge-bd, scene1-edge-cd
  - scene1-midpoint-e, scene1-midpoint-f
  - scene1-line-ef (辅助线)
  - scene1-point-g, scene1-point-h
  - scene1-line-eg, scene1-line-gf, scene1-line-fh, scene1-line-he
  - scene1-label-a, scene1-label-b, scene1-label-c, scene1-label-d
  - scene1-label-e, scene1-label-f, scene1-label-g, scene1-label-h
  - scene1-label-plane-alpha
  - scene1-slider, scene1-slider-angle-display
- IIFE 隔离：所有 JS 代码包在 (function() { ... })() 中，避免全局变量污染
