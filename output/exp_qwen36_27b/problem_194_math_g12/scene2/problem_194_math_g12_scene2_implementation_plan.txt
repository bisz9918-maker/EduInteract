[图示主题与整合说明]
- 本图示主题：利用异面棱垂直关系推导四面体体积公式
- 整合的步骤/概念：从四面体ABCD的几何结构出发，利用AD⊥BC的异面棱垂直条件，逐步推导体积公式从向量形式 V = 1/6 |AD·(AB×AC)| 简化为 V = 1/6 · AD · BC · h，再代入已知值得到 V = 2/3 ch，最终得出求体积最大值等价于求公垂线段h最大值的结论
- 教学价值：教师可通过分步按钮导航，逐步展示从一般到特殊的推导过程，帮助学生理解异面棱垂直条件下四面体体积的简化公式及其几何意义。每一步都有明确的视觉变化，配合公式区的同步更新，使抽象的代数推导与直观的几何图形紧密结合

步骤1：展示向量形式的体积公式

- 新增向量箭头（叠加在对应棱上，用marker-end箭头标记）：

步骤2：利用AD⊥BC推导简化公式
- 四面体保持不变

  - 新增（y=240）："V = 1/6 · AD · BC · h"（黑色16px粗体）

步骤3：代入已知值得到最终表达式

步骤4：强调结论——体积与公垂线段h成正比
- 四面体保持不变
- 公垂线段h加粗闪烁动画（线宽从2px变为4px再变回2px，循环一次）
- 公式区更新：
  - 步骤1、2公式变为半透明（opacity=0.3）
  - 步骤3公式保持绿色高亮
  - 新增（y=370）："V ∝ h"（黑色16px粗体）
  - 下方："求V的最大值 ⇔ 求h的最大值"（黑色14px）
- 控件栏：显示"步骤 4 / 4"，「下一步」禁用

[交互方案]
- 交互类型：分步按钮导航（◀上一步/下一步▶）
- 控件说明：
  - 「◀ 上一步」按钮：位置(230,455)，尺寸100×36px，点击返回上一步骤，步骤0时禁用
  - 「步骤 X / 4」指示器：位置(400,473)，显示当前步骤编号
  - 「下一步 ▶」按钮：位置(530,455)，尺寸100×36px，点击进入下一步骤，步骤4时禁用
- 教师操作流程：
  1. 图示加载后显示步骤0（四面体基础结构），教师可先让学生观察图形
  2. 点击「下一步」进入步骤1，展示向量形式的体积公式，配合讲解向量叉积的几何意义
  3. 点击「下一步」进入步骤2，展示利用AD⊥BC条件简化后的公式，强调公垂线段h的作用
  4. 点击「下一步」进入步骤3，代入已知值得到V = 2/3 ch，绿色高亮吸引注意
  5. 点击「下一步」进入步骤4，展示最终结论，公垂线段h闪烁强调其与体积的正比关系
  6. 教师可随时点击「上一步」回退到任意步骤进行复习或重新讲解

[技术实现]
- JS 库选择：原生SVG（无需额外库）
  - 原因：四面体为简单几何图形，所有元素均可用SVG基本形状（line、circle、text、rect）实现；公式用SVG text元素即可满足需求；交互逻辑简单（按钮点击切换状态），无需复杂动画库
- 画布尺寸：800 × 500 px（固定）
- 布局草图（ASCII）：
  ```
  [图示区 800×500]
  ┌──────────────────────────────────────────────────────────────────┐
  │                                                                  │
  │           D(130,100)                    体积公式推导             │
  │            |                                                       │
  │            |                                                       │
  │            |                                                       │
  │      M(130,240)                                                     │
  │            |\                                                      │
  │            | \ h                                                   │
  │            |  \                                                    │
  │            |   \ N(320,320)          步骤1:                       │
  │            |    \                       V = 1/6 |AD·(AB×AC)|     │
  │            |     \                      步骤2:                     │
  │            |      \                     V = 1/6 · AD · BC · h     │
  │            |       \                    步骤3:                     │
  │            |        \                   V = 2/3 ch  (绿色)        │
  │            |         \                   步骤4:                    │
  │            |          \                  V ∝ h                     │
  │    A(130,380)----B(270,360)----C(370,280)   求Vmax ⇔ 求hmax      │
  │                                                                  │
  ├──────────────────────────────────────────────────────────────────┤
  │              [◀ 上一步]    步骤 X / 4    [下一步 ▶]              │
  └──────────────────────────────────────────────────────────────────┘
  ```
- 关键实现要点：
  1. **状态机设计**：用变量 `currentStep`（0~4）跟踪当前步骤，每个步骤对应一个渲染函数 `renderStep(step)`
  2. **SVG元素管理**：
     - 静态元素（四面体棱、顶点、公垂线段、标签）始终显示，用 `<g id="scene2-static">` 分组
     - 动态元素（向量箭头、公式文本）按步骤显示/隐藏，用 `<g id="scene2-step1">` ~ `<g id="scene2-step4">` 分组
     - 通过设置 `display="none"` / `display="block"` 或 `opacity` 控制可见性
  3. **公式渲染**：用SVG `<text>` 元素，分数用普通文本 "1/6" 表示，向量符号用箭头标记
  4. **箭头标记**：用 `<marker>` 定义箭头，ID为 `scene2-arrow-blue`、`scene2-arrow-gray`
  5. **按钮事件绑定**：用 `addEventListener('click', ...)` 绑定点击事件，更新 `currentStep` 后调用 `renderStep()`
  6. **动画效果**：步骤4中h的闪烁用 `requestAnimationFrame` 实现线宽从2→4→2的平滑过渡（持续1秒）
  7. **公式区背景框**：步骤3的绿色背景框用 `<rect id="scene2-formula-bg" x="470" y="290" width="220" height="40" rx="4" fill="#e8f5e9" />`
- ID 命名规范：所有交互元素和SVG分组ID以 `scene2-` 为前缀
  - `scene2-svg`：主SVG容器
  - `scene2-static`：静态元素分组
  - `scene2-step1` ~ `scene2-step4`：各步骤动态元素分组
  - `scene2-btn-prev`：上一步按钮
  - `scene2-btn-next`：下一步按钮
  - `scene2-step-indicator`：步骤指示器
  - `scene2-arrow-blue`：蓝色箭头标记
  - `scene2-arrow-gray`：灰色箭头标记
  - `scene2-formula-bg`：公式背景框
- IIFE 隔离：所有JS代码包裹在 `(function() { 'use strict'; ... })();` 中，避免全局变量污染
- JS 中用 `document.getElementById()` 而非 `querySelectorAll` 配合全局class，确保多场景合并时不跨场景污染
